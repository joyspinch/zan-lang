# System.Barcode

二维码编解码：完整的 QR Code 模型 1-40 编解码器（ISO/IEC 18004）+ 能从图片里
把码读回来的扫描器。纯 Zan，无反射，无原生依赖。

对标 ZXing.Net 的 QR 子集，但**只做二维码这一件事**：不做一维条码
（Code128 / Code39 / EAN）、不做 Aztec / DataMatrix / PDF417、不做摄像头取流
与 UI、不做多种格式的自动仲裁。

## 设计取舍

### 1. 编码器只有一份，放在包里，Gui 侧只留薄适配

原来的 QR 编码器在 `Zan.Gui`（`Gui.Widget.QrEncoder`，799 行）。现在实现搬到
`System.Barcode`，Gui 侧只剩几十行类型转换（`Gui.Widget.QrEncoder`）。

两份编码器迟早会分叉——掩码罚分、版本选择、容量表这些细节最容易被改坏一边，
而症状是"同样的内容编出不同的码"，极难排查。规则是"公共机制进包"：编码是
公共机制，渲染才是 GUI 的事。

`Gui.Widget.QrMatrix` / `Gui.Widget.QrEcl` **保持不动**（控件在用），适配层做
显式转换：级别逐个枚举映射，模块位图直接搬（两边都是行主序 `bool[]`）。

### 2. 解码器认"图"，不认"二维码图片"

输入是**亮度平面**（`BarcodeImage.FromLuminance`），ARGB 只是便利入口
（`FromArgb`）。接口越窄，越不容易出现"某个调用方传了另一种格式"的错——
色彩信息对二维码判定本来就没用（拍歪了只带来色偏和阴影）。

### 3. 定位图形按"簇"取中心，不取单次命中

二维码的三个定位图形（左上 / 右上 / 左下）是 7x7 的同心方块，黑白比例固定
1:1:3:1:1，所以**扫一行**就能认出来——这与码的内容无关，旋转过的码也一样
（方块沿任意方向切出的比例不变）。

但有个坑：**斜切方块的弦并不关于垂足对称**。切线不过中心时，3 模块宽的深色段
（3x3 中心块）的中点会随扫描行**线性漂移，速率正好是 tanθ**——15° 时行 39→55
中点从 78.5 漂到 74.5。取单次命中的位置会偏半个模块以上，采样直接全错。

正确的取法是**对整个命中带取中位数**：漂移是线性的，而能命中 1:1:3:1:1 的那些
行关于图案中心行对称，中位数正好落在图案中心（中位数而不是平均值：簇里可能
混进数据区的假命中，平均值会被拉偏一两个模块）。

聚类的键用"横竖配对点"（横向中点 x，竖直中点 y）而不是原始命中：**左上与左下
两个定位图形的 x 完全相同**（相隔十几个模块），只按 x 聚类会把它们并成一簇。

### 4. 旋转因子必须显式修正

从图上量到的模块尺寸 m 是"视在"值：方块被斜切时弦长被放大
1/max(|cosθ|,|sinθ|) 倍，所以符号里的真实边长 **s = m · max(|cosθ|,|sinθ|)**。
θ 由三个定位图形构成的直角三角形给出（斜边方向即符号 x 轴）。

不做这个修正，45° 的码会被算成 1.41 倍大，版本直接判错。

### 5. 校正图形在符号坐标系里匹配，不在图像坐标系里

5x5 校正图形是透视矫正的第四个锚点（版本 ≥ 2 才有，在右下角附近）。直接拿
轴对齐的模板去图像里匹配，**码一旋转模板就对不上**。改用"先用仿射把候选位置
投到图上，再按模块中心采样"——模板跟着码面一起转，旋转、斜拍都能用。

25 个格子必须全中才算数：放过一个错的校正图形比没有校正图形更糟（变换会被
带歪）。

### 6. RS 解码用扩展欧几里得，不用 Berlekamp-Massey

一步同时得到定位多项式 Λ 与错误求值器 Ω，公式链更短、每步语义单一（带余
除法），好推理好验证。三条踩过的坑写在 `QrRsDecoder` 的注释里：

- Ω 必须用 `u_k(0)` 归一化（不是 `r_k(0)`）——用错会"位置全对、幅度全错"；
- Forney 公式要乘 **X**（不是 X⁻¹）；
- 特征 2 下负号等于正号，别照抄奇域的公式。

### 7. 预处理是策略，不是单一路径

依次试四种组合，先成功的算：全局阈值 / 全局+去噪 / 局部自适应 / 局部自适应+
去噪。

- **全局 Otsu 优先**：它没有块边界伪影，屏幕截图和打印件上最稳。
- **局部自适应兜底**：应对阴影和不均匀光照。
- **3x3 多数滤波兜底**：椒盐噪声是孤立单像素，会把一条游程从中间劈开，
  1:1:3:1:1 当场就废。滤波把孤立像素抹掉，模块结构原样保留。**不能无条件
  用**：模块只有 2 像素宽时滤波会把整张图抹平，所以它是策略之一而不是默认。

### 8. 错误码可区分，"没码"和"码坏了"必须分开

扫码失败的原因差别很大——"图里没有码"是采集问题（该重扫），"码找到了但纠错
失败"是图像或码本身的问题（该提示用户换个图）。合成一句话会让这些分支都做
不了。

| 错误码 | 含义 |
|---|---|
| `InvalidImage` | 输入图像不合法（宽高为 0、缓冲区长度对不上） |
| `NotFound` | 图像里没找到可识别的码 |
| `CorrectionFailed` | 找到了码，但 Reed-Solomon 纠不回来（污损太多） |
| `MalformedCode` | 码的结构不合法（版本/分块对不上、格式信息纠不回来） |
| `UnsupportedMode` | 码的模式本包不支持（Kanji、结构化追加、未知 ECI） |
| `TooLong` | 内容超出 QR 版本 40 + 最高纠错级别的容量 |
| `Internal` | 内部错误（出现即说明包里有 bug） |

异常自带 `Message` 给人看，异常上的 `error` 字段给程序分支用。

## 能力

| 能力 | 说明 |
|---|---|
| 编码 | 模型 1-40，Numeric / Alphanumeric / Byte(UTF-8) 混合分段，自动选最小版本 |
| 纠错 | L / M / Q / H 四级，GF(256) Reed-Solomon，分块交织 |
| 掩码 | 八个掩码全试，按标准四条罚分选优 |
| 格式信息 | BCH(15,5) 编解码（纠错级别 + 掩码），版本信息 BCH(18,6) |
| 解码 | 读回图像里的码：二值化 → 定位图形 → 变换 → 采样 → 去掩码 → 反交织 → RS 纠错 → 分段解析 |
| 旋转 | 任意角度（0/15/45/90/180/270 已验证） |
| 透视 | 版本 ≥ 2 用右下校正图形做 4 点投影；找不到退回 3 点仿射 |
| 缩放 | 模块 2 像素起（已验证 2..6） |
| 噪声 | 椒盐噪声 5% 以内可读（3x3 多数滤波兜底） |
| 污损 | 靠 RS 纠错还原（盖住一块仍能读出） |
| 渲染 | `QrRenderer.ToArgb` / `ToImage`：纯算术出像素，不出 PNG/SVG 文件 |
| 结果信息 | 文本 + 原始字节 + 版本 + 边长 + 纠错级别 + 掩码 + 模块尺寸 + 四角坐标 |

## 用法

编码并画出来：

```zan
using System;
using System.Barcode;

QrMatrix mx = QrEncoder.Encode("https://zan-lang.dev", QrEcl.M);
Console.WriteLine("v" + mx.version + " size=" + mx.size);
// 画到画布：mx.Get(col, row) 读模块（true = 深色，不含静区）
```

从图片里读出来：

```zan
// 图像库/相机回调给一张 ARGB 图
BarcodeImage img = BarcodeImage.FromArgb(width, height, argb);
try {
    BarcodeResult r = BarcodeScanner.Scan(img);
    Console.WriteLine(r.text + " (" + r.Describe() + ")");
} catch (BarcodeException e) {
    // e.error 是可区分的错误码，e.Message 给人看
    if (e.error == BarcodeError.NotFound) {
        Console.WriteLine("没扫到码，再扫一次");
    } else {
        Console.WriteLine("扫到了但解不开: " + e.Message);
    }
}
```

连续扫码（摄像头预览帧）用 `TryScan`——**每一帧都可能没有码，那是正常情况，
不该被异常打断**：

```zan
BarcodeResult[] slot = new BarcodeResult[1];
if (BarcodeScanner.TryScan(img, slot)) {
    Handle(slot[0].text);
}
```

想自己控制低层（自己二值化、自己定变换）就直接用 `QrDecoder`：

```zan
QrDecoder.QrDecodeResult r = QrDecoder.Decode(img);
Console.WriteLine(r.text + " mask=" + r.mask);
```

## 并发边界

- **全部静态方法，无共享可变状态**：编码、解码、渲染都不写任何全局变量，
  多次调用互不影响，**多线程安全**。
- 解码全程只读输入图像，不修改调用方的缓冲区。
- 每次 `Scan` 独立分配中间缓冲（图像副本、二值化平面、模块矩阵），调用结束
  即释放；大图上这是主要开销来源（见「已知边界」）。

## 验证

conformance `barcode_qr`（42 条断言）：

- **编码指纹**：固定输入 -> 固定位图（深色模块数 + 加权和），编码器一动就变。
- **往返**：ASCII / 纯数字 / URL / UTF-8 中文 / 单字符五种内容，文本、版本、
  边长、纠错级别四项都要一致。
- **旋转**：0 / 15 / 45 / 90 / 180 / 270 度都要读得回。
- **缩放**：模块 2..6 像素都要读得回。
- **噪声**：椒盐 2% / 5% 都要读得回。
- **污损**：盖住一块靠 RS 纠错还原。
- **错误码可区分**：数据区大面积损坏 -> `CorrectionFailed`；空白图 -> `NotFound`；
  空图 -> `InvalidImage`；超出容量 -> `TooLong`；容量边界（v40-L 的 Byte 容量
  正好 2953 字节）卡准。
- **TryScan**：没码返回 false 不抛异常，有码时结果写进出参。

编码器与 Gui 原有实现逐模块比对过（9 组文本 × 级别，含中文与 URL），搬迁
没有改变任何一个模块。

## 已知边界

- **没有一维条码**。Code128 / Code39 / EAN / ITF 不在本包范围内。
- **不做多种码制仲裁**。只认 QR；图里是 DataMatrix 会报 `NotFound`。
- **不做摄像头取流与 UI**。本包只处理"已经拿到的一张图"。
- **不出 PNG / SVG 文件**。文件格式是 `Zan.IO` / GUI 层的事；本包只产像素
  （`QrRenderer.ToArgb`）。Gui 侧 `Gui.Widget.QrCode.PngOf` / `SvgOf` 仍然可用。
- **不支持 Kanji 模式、结构化追加、ECI 自定义字符集**：解出来抛
  `UnsupportedMode`（可区分，不静默出错码）。ECI 的默认字符集按 UTF-8 处理。
- **透视矫正依赖校正图形**：版本 1 没有校正图形（ISO 规定从版本 2 才有），
  只能退回仿射；版本 ≥ 2 找不到校正图形时也退回仿射（斜拍厉害时可能读不出）。
- **解码是全图扫描**，没有"大概在哪"的先验。超大图（几千万像素）会慢；先
  自己裁剪或降采样再喂进来。
- **不做多码并列**：一张图里有多个码时，返回其中**先被解码成功的那一个**，
  没有"列出全部"的能力。
- **不做连续帧跟踪**（上一帧的码在哪、这一帧往哪移）。

## 放置

`packages/Zan.Barcode` —— 命名空间 `System.Barcode`，**不依赖任何其它包**
（图像格式转换由调用方做：图像库给 ARGB，本包收亮度平面）。
