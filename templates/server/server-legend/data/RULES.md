# 玩法规则台账（唯一真相 + 冲突裁决）

服务端 `src/Game/Fight.zan`、`src/Game/Play.zan` 里的每一个玩法数字都必须能在
`data/rules/*.csv` 里找到出处；代码里不留常量。本文件回答两件事：

1. **规则真相以谁为准**（三方冲突怎么裁决的）；
2. **哪些数值是我重新设计的、依据是什么**（原值为什么不合理）。

规则表不是手写的：编辑源是 `templates/game/legend/data/`（客户端离线模式也用
同一份），`tools/sync_rules.py` 单向复制到这里，`--check` 模式在两侧不一致时
报错退出。因此「客户端一份 + 服务端一份」不会各自漂移。

---

## 一、真相优先级

原版资源里同一件事有三个说法，冲突时按下面的顺序裁决，**上位覆盖下位**：

| 优先级 | 来源 | 位置 | 用途 |
|---|---|---|---|
| 1 | 原版游戏说明 | `templates/game/legend/mir2/mir/说明.txt` | 玩法语义（次数、时长、爆率、产出、解锁条件） |
| 2 | 原版数据表 | `data/M2.DB` 的 `Game*` 表 | 原版逐行事实（称谓名、爵位门槛、城池收益…） |
| 3 | 产品设计文档 | `templates/game/legend/mir2/传奇放置挂机游戏-产品设计文档.md` | 界面与流程描述 |
| 4 | 模板既有 CSV | `data/rules/*.csv` | 数值占位：与上位冲突时改 CSV，不改上位 |

第 4 条是关键：CSV 是**可变层**，不是真相层。旧服务端把 CSV 当真相用，于是
`world_tries=2` 与说明.txt「挑战次数与 BOSS 之家共享」直接矛盾，而「共享」这
条被丢掉了。

## 三、重新设计（原值本身不合理）

### 3.1 转生经济：`rebirth.csv`

原值：金币 `3000 → 30000`（10 转合计 16.5 万），等级门槛 `30 → 75`。
**问题**：挂机第一天就能全转完，转生完全失去长线意义；说明.txt L235 明说
「巅峰之前一共转生需要大概 28 亿金币」。

新值：`95000 × 1.5^(n-1)` 量级（首转 2470 万，十转 9.5 亿），十转合计
**27.99 亿**，正对说明.txt；等级门槛 `30/60/120/200/300/420/560/750/1000/1300`，
幻境门槛 `15/40/90/160/260/400/600/900/1400/2000`。

```python
g = 24700000.0; steps = [round(g * 1.5**i, -4) for i in range(10)]   # sum ≈ 2.8e9
```

单步必须 `< 1e9`：客户端金币是 `int`，`Rules.Bounded` 的封顶也是 1e9
（`Data.zan:7`）。等比 1.5 是能同时满足「合计 ≈2.8e9」与「每步 <1e9」的最小
公比，比 3 更平缓也不至于让首转太贵。为此 `rebirth.gold` 的 schema 上限从
`100000000` 提到 `1000000000`（与货币量级一致）。

### 3.2 掉落权重：`drops.csv`

原值：234 行 `weight` **全是 1** —— 权重字段形同不存在，所有掉落等概率。

新设计：表里的 `weight` 降级为「稀有度基准」，真实权重由稀缺度修正
（`Rules.WeightOf`）：

```zan
稀有度 = drop_value_pivot * 1000 / (sell_price + 1)      // 越贵越稀
真实权重 = max(1, weight * 稀有度 / 1000)
```

理由：说明.txt L50 要求「转生证明/渡劫证明爆率 ≈1/10，属性符文 ≈1/500」——
差了 50 倍。逐行手调 234 个数字既不可审计也不可复现；用售价反推能让策划改
一个 `sell_price` 就同步改爆率，且量级关系是可推导的。

### 3.3 BOSS 掉落池：`bosses.csv`

原值：28 只 BOSS **全部** `drop_pool=1`（新手池），与说明.txt L48-51 的分段
定位完全脱节。

新设计按说明.txt 分段配池（池 25-35 原本只有木剑，是空池）：

| BOSS 编号 | 池 | 产出 | 说明.txt |
|---|---|---|---|
| 1-5 | 25 | 前期装备 | L48「编号 1-5 的 boss 是前期装备的来源之一」 |
| 6-14 | 26 | 一~十转证明 | L49「编号 6-14 的 boss 是转生证明的来源」 |
| 15-23 | 27 | 龙珠 1★~9★ | L50「爆的龙珠是 500 级制作传说装备的材料」 |
| 24-28 | 28 | 渡劫证明 ㈠~㈤ | L51「500-900 级渡劫证明的来源」 |

为此在 `items.csv` 里补齐这些材料（表里本就有 732 行原版物品，此前只是没人
把它们接进掉落池）：一~五转证明 348-352、六~十转证明 440-444、巅峰证明 497、
巅峰矿石 498、龙珠 1★~9★ 644-652、渡劫证明 ㈠~㈤ 681-685 与 (六)~(十)
707-711、周年庆号角 689、黑铁矿石 223、金条 224、金砖 225、沃玛号角 330、
祝福油 217、一~三级宝石 543-545。

同时放开 `Tables.zan`/`Rules.zan` 里「池内必须装备」的约束：掉落的
`item_id` 必须存在、且不能是货币占位（`id <= 10` 是金币/元宝/经验…），但**允
许非装备材料**——否则上面这些证明、龙珠、宝石一个都进不了池。

### 3.4 幻境层数溢出（172 层以上无内容）

原值：`maps.csv` 只覆盖到 171 层（巅峰塔⑩），而 `max_floor` 允许到 10000。
172 层之后的地图/怪/金币/经验全部退化成末图。

新设计：新增两条规则键，超出末图后按层缩放：

| 键 | 值 | 含义 |
|---|---|---|
| `floor_scale_per_100` | 8000 | 每高 100 层，倍率 +0.8（万分比增量） |
| `floor_scale_cap` | 50000 | 倍率封顶 5.0 |

`Rules.FloorScalePermille(floor)` 实现，`Rules.MapAt(floor)` 取「最后一个
`start_floor <= floor` 的地图」。这样 2000 层的转生门槛才有对应内容。

### 3.5 四种货币闭环

原值：声望 / 战功 / 红包 / 积分的**唯一来源是回收**，换算比 1/1000~1/10000
（等于没有），但它们却是称谓 / 爵位 / 红包 / 回收集市系统的消耗币 —— 只有出口
没有入口。

新设计给每种币配了玩法产出：

| 币 | 出口 | 新增入口 |
|---|---|---|
| 声望 reputation | 称谓解锁（说明.txt L226「占领声望城池、红包开出、幻境活动」） | `escort_merit=30`（押镖）、师徒奖、占城 |
| 战功 merit | 爵位 / 传说塔 | `tower_merit=20`（爬塔）、`arena_win_merit`（竞技场） |
| 红包 redpackets | 红包池 / 幻境重置 | 幻境层产出、`redpack_share_pct=50`（红包拆分） |
| 积分 recyclePoints | 回收集市 | 回收装备 + 幻境 |

| 史诗 | 1 | 4 / 6 |

## 四、校验：错配置要在启动时炸，不是运行时算错

`Rules.Validate()`（服务端）与 `GameTables.Validate()`（客户端）用**同一套
schema 字符串**校验同一批 CSV，任一列/列范围变更都会在另一侧加载期失败。除
schema 外还查：

- 五行 5 行、回收币 7 行、内功 8 位、宝石 6 颗、属性 12 项、槽位 12 / 品阶 5 / 职业 3；
- `sets` 引用的物品必须存在且可穿戴；`recycle_prices` 引用的物品必须存在
  （原表要求「必须可穿戴」，会把无槽位的贵重品如幸运雪莲排除，已放宽为存在性）；
- 技能 3 职业 × 8 槽**每格恰好一个**；
- 品阶系数不可回退；宝石合成上限 < 普通上限；
- 地图 `start_floor` 严格递增、首图为 1、地图与 BOSS 的 `drop_pool` 非空、
  掉落引用的物品存在且非货币占位；
- 必需键一个不缺（含 `incoming_random_min` / `incoming_random_range`）；
- 次数预算为正，进度上限 `progress_cap_mode ∈ {fixed, level_plus}`，
  幻境/怪物/BOSS 的攻防区间不反转。

## 五、持久化与并发的统一边界

旧服务端最大的体验缺陷是**同类玩法两套语义**：城池/沙巴克/红包池/世界 BOSS
重启清零，而 BOSS 链进度/五行落库 —— 玩家无法预期。

新设计：

- 所有跨重启可见的世界态走 `world_state(realmId, key, value, version, updatedAt)`，
