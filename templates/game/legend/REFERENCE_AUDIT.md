1. 容器 `Padding` 的**底部内边距不计入容器测量高**——最后一行会贴到外框上
   （表底落 802，应 811）。上下留白必须用**定高撑条**显式占位。
2. 行节距实测 **49.5 设备**，整数设备像素下只能是 49/50 交替。**原版自己就是
   交替的**（行顶 214/263/313/362… 差 49/50 混排）；全用 49 会让第 12 行低
   6 设备、表底落 804。用 `TblRowHAt(r) = RowH + (r % 2)` 复现。
3. `Panel.Row()/Column()` 会置 `layout`，`With()` 据此把子项 dock 改成 3/1。
   要在格子里**手动摆位**（如居中的「领取」钮）必须用 `Add()` + `DockManual()`
   + `Place()`——用 `With()` 会贴左并拉满行高（实测偏 9/9 设备）。
4. **`text-align` 对 `Label` 无效，居中必须靠格子的 flex `justify-content`**。
   `Label.OnPaint` 直接在盒子左缘 `DrawText`（`StyleBox.DrawLabel` 才认
   `text-align`，Label 没走那条路），所以 `.tbl-c0 { text-align: center }` 是
   死规则——第一版整表文字贴左、与原版差 **29 设备**。正解：格子挂
   `.tbl-head-c / .tbl-cell { display:flex; justify-content:center;
   align-items:center; }`，标签按自身测量宽参与 flex 排布。高亮行的格子要
   同时挂 `.tbl-cell` 与 `.tbl-cell-hl`（后者只覆写底色为透明）。
5. 页脚右端靠 `.bag-fill`（`flex-grow:1`）顶开，**容器必须是
   `display:flex`**（`.tbl-foot`）；不是 flex 时 flex-grow 失效，右侧一组会
   紧贴状态文字（实测整组落 531..930，应 1152..1481）。
6. 标准库 `Pagination` 默认按主题 `heightMedium`（34 逻辑）出钮，比原版页脚
   高一大截。皮肤加 `pagination { height: 20; font-size: 12; }` 收紧。
7. 页脚左组**组距不等**（279/245 设备），用 `Gap` 凑不出来——每组一个定宽盒，
   且宽度要**扣掉页脚容器自己的 4 设备缝**（`LordFootCol1W = Px(184)` 对应
   392→671）。

## 十一、本项目布局定式与框架偏差（非原版实测，改动前先读）

原版是那个原版，但**本项目的实现有几条用户拍板/框架逼出来的定式**。
它们不是"原版实测值"，所以单独列在这里；`Spec.zan` 是这些值的唯一出处。

### 11.1 竖向节奏只有一个间距

`ContentTopPad = BotTileBottom = NavRowGap = Px(4)`（150% 屏 = 6 设备像素）。
原版顶栏瓦片直接贴标题栏（顶 0）、底下却空 12.7 逻辑像素，用户点名
**「按钮贴顶了下面有间距，这也是不行的，上下间距要是一致的，最好和按钮
之间的间距也统一」**。改后实测：标题栏下 6 / 两行瓦片间 6 / 瓦片行下 6 /
底排瓦片下 6，四段全等。

### 11.2 顶栏整行左移 8 逻辑像素 + 右端与左端留白配平

`NavRowShift() = Px(11) - LeftPad()`。原版第 1 格实测 x=11，比正下方左栏
面板左缘（3）缩进 8，看着不齐；用户要求**「按钮左移，对齐下面」**。瓦片
宽与格间隙仍是实测值，只有这一行的起点偏离原图；改后顶栏瓦片、左栏面板、
底排瓦片左缘实测都在 x=4（设备像素）。

左移后右端离聊天面板还有 43 设备像素，而左端只有 4，用户：
**「这个右侧应该跟左侧间距保持一致」**。第一次实现是"格间隙均分铺满"，
被否：**「之前按钮的间距是可以的，是要整体左移 不是该按钮」**——间距是
实测值，不许动。最终定式（用户：**「两排按钮各自增加几个像素宽也能达到
对齐效果」**）：

- 每排**行末加一条 `LeftPad` 宽的撑条**，行首边距与行末边距相等；
- `.nav-row { display: flex }` + `.navtile { flex-grow: 1 }`：行里剩下的
  宽度**平分给各瓦片**（按钮各宽几个设备像素），撑条（flex-grow 0）不动，
  所以**格间隙逐条与实测一致**；`.navtile-gear { flex-grow: 0 }` 让设置
  齿轮保持正方形（33×33 逻辑），余数由引擎给最后一个可增长项
  （`ArrangeFlexLine` 的余数规则），每排右端因此**落在同一列**：
  实测三排右缘都在 1507..1509，聊天面板左缘 1513，左端 4。
- 三排（顶栏两排 + 底排）右端同列，与原版一致（原版三排右缘同为 988 逻辑）。
- **坑**：`Panel.Row()` 默认走**停靠布局**（`With()` = 左停靠），不做剩余
  空间分配，只按各控件的 `StyleWidth` 摆位——只写 `flex-grow` 而不给容器
  `display: flex`，`flex-grow` **一点作用都没有**（本轮实测一次踩空）。

### 11.3 窗口高 625（原版 646）——"元素整体上收"

`Spec.WindowH()`。卡阵在主区里居中后，上下留白比左右各多 17 逻辑像素，
收掉这 17 两边才配平；用户原话**「整个窗口高度应该可以缩小一点啊，
元素整体上收」**。实测窗口从 1888×1019 收到 1888×993（设备像素）。

### 11.4 地图传送页（页 0）的竖向定式

用户原话**「地图不是垂直居中的啊」**。定式：
- **卡阵在主区里垂直居中**：`topInset = (pageH - wallH) / 2`（下限 `MapMargin`），
  实测上下留白 80 / 82 设备像素（含标题栏后的 6）。
- **页码贴主区底**（原版页码本来就在左下）、与卡阵左缘对齐：`pagerTop =
  pageH - MapMargin - PagerH`，撑不下一个卡阵行距（`MapRowGap`）时退到卡阵
  下沿。5 行卡阵居中后底下只剩约一个行距的余量，所以实际是"紧贴卡阵下沿"。
- **`.map-page` 不许再留 CSS padding**：它曾在 CSS 里留 8 逻辑像素，等于从
  主区上下各偷 12 设备像素，而 `pageH` 是按整块主区算的 → 块被挤扁 24 像素，
  居中看着对、实际靠"挤"对齐（实测 pager 被裁掉 2 像素）。间距一律在布局
  代码里算，不在 CSS 里留。

### 11.5 框架偏差（记录在案，**不在 Zan 侧绕**）

1. **无边框窗口的客户区被 OS 撑大**：150% 屏上 `Win32Shell` 建窗/`ResizeClient`
   仍按 `AdjustWindowRect(WS_OVERLAPPEDWINDOW)` 给无边框窗口加了一圈外框，
   实测画布比设计尺寸大 **(22, 56) 设备像素**（设计 1866×963 → 实到 1888×1019）。
   → 所以**一切居中必须按运行期画布算**（`app.ClientWidth/Height()`），拿设计值
   居中会偏右偏下。
2. **页面要在窗口尺寸变化后重建**：`SetClientSize` 之后画布要等窗口处理完
   resize 才变，紧接着建页会拿着 resize 之前的旧画布算（实测算出 494×427，
   只有真实主区 1138×788 的一半，两个 inset 都撞下限，卡阵被顶到左上角）。
   现在 `main.zan` 用 `form.Every(120, ...)` 轮询客户区尺寸，变了就 `BuildPage()`。
   **尺寸必须"重建成功后"再记下**——记在重建之前，一次异常就会把这次 resize
   永久吞掉，窗口停在旧布局上。
