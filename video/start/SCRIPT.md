# Zan ·《你不需要会写代码》/ NO CODE REQUIRED
### 18 秒 · 固定机位 · 一镜到底 · 无缝循环 · 品牌短片脚本 v4

> **v4 立论（推翻前三版）**：前三版都在说"语法像 C#，程序員上手快"。
> 这个前提是错的——**AI 会写代码，人不需要会编程。**
>
> 这门语言真正的精髓：**让 AI 写出来的东西变成真的原生产品，而不是一段跑不起来的片段。**
> 它给 AI 的是一套可验证的工具链（查 API → 写 → 编译 → 看诊断），
> 而界面层用 HTML/CSS——AI 最擅长的表达，编译出来却是原生窗口，不是网页。

---

## 1. 为什么要有这门语言（片子的骨）

| 今天 | 代价 |
|---|---|
| AI 能写代码，但交给你的是**四份**（每平台一套：WinUI / Compose / SwiftUI / React） | 你还得自己拼、自己维护四份 |
| AI 写的 API 常常是**编的**，编译报错它看不见 | 人肉来回贴，最后不了了之 |
| 用 HTML/CSS 做界面最快，但只能进浏览器 | 拿不到原生窗口与系统能力 |

**Zan 的答案**：AI 查得到真 API（MCP `zan_lookup_symbol`）→ 写 HTML/CSS + C# 风格逻辑 → `zanc` 编译出**原生**窗口（LLVM AOT，无虚拟机）→ 一份源码出七个原生目标。
人只需要说清楚想要什么。

## 2. 时间轴（18.0s，机位不动）

| 时间 | 画面 | 字幕 |
|---|---|---|
| 0.0–3.5 | 四块 AI 写出来的窗口从中心展开：WinUI / Compose / SwiftUI / React，**同一个待办界面**，各盖 `REWRITE #1–4`；React 那块带地址栏 | `01 / 现在` **AI 早就会写代码了。** `C# · KOTLIN · SWIFT · JAVASCRIPT` |
| 3.5–5.2 | 四块塌回中心 | **可交到你手上，还是四份。** |
| 5.0–7.4 | 顶部出现 AI 工具链面板：`zan_start_here` / `zan_lookup_symbol` / `zan_compile ok · 0 diagnostics` / `zan_change_impact`；下方是 AI 写出的 `app.html` + `app.zan` | `02 / 现在 AI 写` **它查得到真 API，也编译得通。** |
| 7.3–10.6 | 代码卡左移，右侧原生窗口自顶向下"长"出来（每亮一行标记→一块控件），最后系统标题栏扣上；底部 `zanc app.zan --publish` 与产物行 | `03 / 编译` **编译成原生。不是网页。** `LLVM AOT · 无虚拟机 · ARC` |
| 10.9–14.3 | 窗口分裂成七块：Windows / Linux / macOS / Android / iOS / WASI / OpenHarmony，同界面、不同标题栏 | **一份源码，七个原生目标。** |
| 15.0–18.0 | 七块收回，落版 | `zan.` **你不需要会写代码。** `说清楚想要什么 · AI 查得到 · 编得过` |

循环：t=0 与 t=18 都是空场（四块窗体 scale 0），首尾同构，无白闪。

## 3. 关键取舍

- **不要蓝色大 logo**：它会打断整片的暗场调性。品牌只靠结尾手绘字标 `zan.` 承载。
- **不要运镜**：固定机位，构图精确到像素。
- **AI 工具链必须上屏**：`zan_lookup_symbol` / `zan_compile` 是本片唯一的"特色证据"，比任何形容词都硬。
- **HTML/CSS 与原生窗并置**：左边标记，右边控件，逐行对应——证明"标记即界面"。
