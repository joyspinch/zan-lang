# 迁移与复刻：尽可能还原原版的功能与使用体验

> 提炼自两场真实迁移（逐窗体复刻一个 C# 商业软件 ~120 个窗口；以成熟产品为
> UX 参照做同族新工具），累计 2200+ 次编辑。用户反复纠偏的每一条都在这里。
> 适用于"迁移/复刻/还原"，也适用于"参照 A 产品做 B 平台的新工具"。

## 第一纪律：复刻，不创造、不阉割

- **原版所有可见按钮、窗口、菜单都是正在使用的功能。** 不要替原作者判断
  "这个大概没用"而省略——你省掉的每一个都会被用户点名。
- 每一个自创的控件、按钮、文案、交互（"这个取消按钮你是从哪里创造出来的"）
  都会被打回。拿不准就去看原版对应窗口的 Designer/事件绑定，没有就是没有。
- **原版的字面 bug 也要 1:1 保留**（阈值取错字段、上限写死、状态码复用）。
  修不修是原版作者的决策；迁移者修掉，用户的行为对照就断了。可单独记录
  成"疑似原版缺陷"清单供人工决策，但代码先保持一致。
- 死控件也照搬：原版窗口里留着的旧控件是用户视觉记忆的一部分。
- **数据与路径口径也是功能**：数据落盘目录、配置文件位置、内嵌浏览器
  userdata 路径尽量与原版一致——目标是把用户的迁移成本压到零。

## 开工前：建立可追溯的映射账本

- 先盘点原版**全部**窗体/页面/菜单，建立 `原窗体 ↔ 新文件` 映射表；
  找不到对应关系的代码不允许进主干目录。
- 命名可追溯：新文件名/类名/注册键从原窗体名推导；每个新窗口头部注明
  源自哪个原窗体——后续差距审计全靠这行注释配对。
- **字段/协议命名照搬原平台原始命名**（含大小写），中文只是单元格显示值；
  禁止自造别名、禁止"数值列+文本列"成对出现——第二套命名意味着每迁一个
  接口都要做一遍翻译，很快就会对不上。
- 实体类逐字段照搬（类型语义映射记录在案：可空→非空+缺省值一致，持久层
  特性丢弃但语义保留）。
- 排版允许重排（用目标框架的方式重新布局），**结构和功能不允许重造**。

## 先对账本，后动手：把返工从"事后发现"挪到"事前确认"

一场 634 文件的迁移返工清单全是同一种形态：代码写完之后才对照原版，发现
字段名、判断口径、循环边界错了，再单独补刀——每条返工都是一整轮
编译+验证。这些返工在动笔前各花 30 秒就能避免：

- **写一个方法之前，先打开原版对应方法逐行读一遍**（DoTask/事件处理器），
  核对四件事再动手：作用的数据字段名、操作的行集合（勾选集还是当前行）、
  循环的粒度（每组一次还是每行一次）、判断用的集合是过滤前还是过滤后。
  实证返工：批量改标题窗体先按自创口径写完内层循环（对每组遍历全部创意、
  重复提交），再对照原版重写；卖点判断用未过滤集合判 Count，原版是过滤后。
- **字段名从 schema/接口定义处抄，不从记忆写**：写 `SelectedIds("...")`
  之前 grep 一下 schema 定义行，确认键名是 `title` 还是 `creativeName`。
  实证返工：整窗补丁打完才发现键名错，再补一次编辑。
- **多步文本手术写成带锚点校验的补丁脚本**（`_scratch/` 下），每处替换
  `if s.count(old) != 1: print("ANCHOR FAIL"); sys.exit(1)`——锚点不符立即
  中止，禁止"找到哪儿改到哪儿"的半套用状态；逐 tag 输出 ok，出问题可以
  定位到步。补丁脚本自身也要过一遍逻辑再跑（一场迁移里补丁脚本自己
  修了两轮：漏去重、比较变量名笔误）。
- **文案/标题逐字核对原版再写端口**，不凭记忆迁移（8 个通知窗体的标题
  就是逐字 grep 原版 Designer.cs 校准的）。

## 行为保真：交互语义逐项对齐

- **操作的目标集合要同原版**：勾选行 ≠ 当前单元格——批量操作作用于勾选集，
  单行操作作用于当前行，复制/复制标题/删除全部按此区分。这是最容易被
  做错、用户一用就发现的语义。
- 右键菜单逐项补齐（含图标）、删除类操作必须有确认弹窗、快捷键一致。
- **一切数据来自接口/原数据文件，不捏造**。演示数据只是骨架期的脚手架，
  接口接通后清除干净——界面上残留假数据=用户以为功能坏了。
- 有限流的接口：客户端与服务端各做一层本地缓存（如 sqlite，按店铺/账号
  分域），缓存命中策略本身就是行为的一部分。
- 表格类的固定列、合计行、列集与列宽（报表几十列的列集是功能不是细节）、
  表头默认高度，都要迁移。

## 使用体验保真：约定统一，形态可升级

- 弹窗约定全应用统一：提交/确认按钮在**右下角**（提交在前、取消在后），
  主体区域填满窗口；子窗口自带标题栏，正文**不要**再重复一个大标题。
- 每个操作要有可见反馈（状态栏回报/进度/结果提示），静默成功=没成功。
- 控件形态可以升级（原版的单选组改下拉、自拼日期区间换目标框架的区间
  组件），但**把原版附带的快捷项一并带上**（日期快捷选择、全选联动），
  且交互结果等价——形态差异属于排版层面，功能缺项不是。
- 整体字号比原版大了一号 → 调**全局字号档位**，不要逐个控件改。
- 字体发虚、边缘毛刺是渲染回归，立即排查修复，不要接受"看起来差不多"。
- 标题栏图标等 chrome 元素不随正文缩放联动——改一处不能带歪另一处。

## 与原版的刻意差异（这些不算"没还原"）

- 原版有 DPI 缩放/小屏适配问题的**像素尺寸不照抄**：窗口大小按内部组件
  排布推导，控件尺寸走目标框架的档位 token。
- 对齐、间距、颜色走目标框架的样式规范（见 `gui-design` skill），原版的
  排版瑕疵不继承。

## 语义照原版，写法归 Zan：不搬运源语言的思维惯性

- "照原版"的边界止于**功能与交互语义**：用户看得见的行为 1:1，用户看不见的
  代码层 100% 用 Zan 的方式写。原版源码是**行为规格说明书，不是实现模板**——
  逐行直译会把旧语言的形状（弱类型、表驱动、回调嵌套、全局可变状态）整体搬
  进来，之后每个新功能都被迫顺着旧形状继续长。仓库 A15 的 workaround 债就是
  这么攒出来的（AGENTS.md 规则 10：修编译器，不要绕过编译器）。
- **动手实现一个能力之前，先查 Zan 有没有**：`zan_api_search` / `zan_example`
  先行，标准库有的能力不许手搓——手写循环拼字符串而不走 `string` API、手撕
  协议报文而不用现成编解码、自建消息队列模拟事件而组件本就有事件、忙等轮询
  而不用 `async/await`，都是"用原语言的思维写 Zan"：慢一倍，还多一堆错。
- **数据形状换成本平台的惯例**：源语言"什么都能塞一张表/一个对象"的地方，
  迁过来就是 Zan 的强类型类 + 显式字段；Zan 明令禁止的（`Any`/动态取属性、
  字符串拼数据结构），原版那么写了也不许照搬——外部行为保留，内部形状不保留。
  aardio 迁移已实证：弱类型表改强类型类后，字段拼写错误从运行期回到编译期。
- **实现中发现"Zan 好像缺这个能力"时，先用最小探针确认**；真缺就记进账本/
  缺口清单（该修组件层或编译器的走对应层），不许顺手在应用层自造影子库——
  影子 API 与标准库重复、无人维护，下一个人会在同一个地方踩两遍。

- **列表/表格数据一行一实体，不要平行列**（2026-09-11 传奇四张表格页被用户
  点出）：`List<string> names / levels / ids …` 靠下标对齐，某列长度对不上就
  静默串行；数值列存成字符串（`"巅峰1500级"`、`"50,1300"`、`"1,0000"`）后
  排序/比较/换格式都要回头解析、格式规则无处校验；还会长出"每渲染一行新建
  一个 12 元素 List 再取下标"这种形状。正解：`class Row { name; job; id; peak;
  exp }` + 显示方法（`LevelText()`）收进实体，格式化助手集中（万位分隔、百分
  号各一处），页面循环只读实体，动作回调收实体不收下标。改造验收 = 同一页
  像素 dump 改前改后**零差异**。原版截图数据只有一屏时也照此写——实体是接
  真实数据后排序/筛选的前提，不是"以后再说"。

## 修 bug 的位置：组件层的问题在组件层修

- 目标框架的标准组件突然坏了（选项卡不能切换/不能关闭），根因几乎总在
  组件内部或此前某次应用层样式改动越了权——去组件里修。在应用层给组件
  "加防线/兜底判断"绕过是被明确否定的方向。
- 应用层的排版改动**不应该能**改变系统组件的交互行为；出现了就是层界破了，
  先修层界再修表现。
- 删除控件时把它的布局槽、命中区、残留状态一并删掉——"设置删了，位置还在"。

## 验证闭环（每一轮都做）

- 编译零错误 + 冒烟：启动后进程存活、无未处理异常，验完清理自己的进程。
- **按窗体/模块小步编译，不攒批**：每迁完一个窗口立即编译——攒一大批再编，
  一旦编译被卡（并发会话冻住的 stdlib 文件、环境损坏），整批改动全部处于
  "未验证裸奔"状态，回溯成本随批大小线性涨。编译被外部文件阻塞时，先声明
  阻塞并停下该批次，不要"先改代码、延后编译"。
- **报"修好了"之前，必须先启动、实际操作被投诉的那个交互、看目标窗口的
  截图**——"没改啊"被连说三遍的教训：没验证的"已修复"等于没修。
- **宣称成功必须有落盘证据**：日志文件非空、标记文件存在、截图可见，
  三者之一才算数。一场迁移的 8 个 repro 变体日志全是空的，"成功"是想象
  出来的，基于它的"修复"自然全部落空。空日志=实验作废，重做实验。
- 截图必须锚定自己启动的那个进程/窗口（规范见 `testing-gui-screenshot`
  skill）；"截图都截不明白"在真实会话里反复发生，且直接把修复带偏。
- 静态改动（对齐/尺寸/样式）之后，**把受影响组件的交互回归一遍**（切换、
  关闭、滚动、选择）——只看静态外观，交互坏了要等用户来发现。
- 大范围改样式/重构前，先确认当前基线是"好的"并提交；否则坏了没有退路，
  也没有对照。**每个确认修好的功能立即 commit**——"之前改好的怎么又没了"
  多半就是没提交被后续改动覆盖。
- 阶段性做**差距审计**：原版窗体清单 × 新窗口清单逐对核查（可按业务域
  分组并行），产出差距报告，三栏：已修复 / 待修复 / 判定不适用（必须带
  证据，如"原版该列为纯文本直填，无图片单元格"）。审计驱动下一轮排期，
  不靠感觉判断"迁移完成度"。

## 素材台账：先确认"这一片是一张图还是 N 个精灵"，再决定画法

复刻老端的网格/列表时，最容易犯的错是**把一张整图当成 N 个单格去拼**，
或反过来。判定方法（背包页实例）：

- **扫边框线数节距**，不要目测。沿网格一条带逐像素扫亮度、把连续亮列聚类，
  得到的就是真实的列/行边界（背包实测竖线 x = 758 + 59.7k，k=0..12 → 12 列，
  目测会数成 6 列或 11 列，差一整列）。行列数一旦错了，底图 stretch 上去
  格子就对不齐。
- **拿素材包的整图去对格数**。`ui/00083.jpg`（488×249）逐条线扫出来正好是
  12×7 格，与实测的 12 列 × 7 行**一一对应**——它就是物品栏的整张底图，
  `stretch` 到实测尺寸即严丝合缝。**把原版格子逐个画出来是自绘**：
  用户一眼就能看出"格子是这样一个个画出来的吗"。
- **单格精灵另有归属**：`ui/00211.png`（45×43 石块格）不是主物品栏的格，
  而是「取出/仓库」那种表格里的格；`ui/00210/00255.png` 是锁标志。
  台账 csv 的 `module_guess` 只是猜的，**用之前必须亲眼看图**。
- 结论写进 REFERENCE_AUDIT 时带上"用哪张整图 / 哪些是精灵 / 哪些原版根本
  没有素材（如物品栏空位的问号是客户端字体画的）"，并标注为素材缺口。

## GUI 复刻：列表/表格页用组件拼，不逐页手摆坐标

复刻一个老客户端的几十个界面时，**先找/先造一个列表组件，页面只给数据**——
用户原话：「列表类不是写一个组件列表输出即可吗，不需要每一个都去抠位置」。
逐页手摆坐标的真实代价是每加一页都要重来一遍对位，且改一处间距要全页重测。

- **一行一实体**：一行数据一个类/结构（`{列名→值}`），不要平行数组靠下标对齐。
  踩过：称谓页的魔法列拿攻击列的值判颜色，两列数值一不同就串色。
- **数据值可以后接服务端，字段结构现在就定死**。用户原话：「很多数据最终都是
  靠服务端下发的，现在是要做 Ui 的准备工作」——占位值只要结构对就行，别为抄
  准某个数字反复回去量图。
- **骨架分横竖两种，装错不报错、只是静默叠成一列**。踩过：`mk-frame` 的 CSS 是
  `flex-direction: column`（给「顶带+中段+页脚」的页用），拿它装「左内容+右列表」
  的两栏页，结果是左栏拉满整宽、右栏塌成 0 高——编译、运行、点导航全都不报错。
  两栏页要用横向框（同一套面板的宽高照抄已落地的同类页）。
- **`Grow()`/`dock=5` 是第二趟布局**：撑条放在兄弟**前面不占位**（内容照旧从顶排、
  撑条吃剩余），要固定间距就用**定高撑条**或 `DockBottom()`。踩过：底行因此高 38 设备。
- **`Column` 的 `Gap` 是「每两个子项之间」**：网格前导再放一个撑条会变成「撑条+缝」，
  顶距被算两遍。要顶内缩用容器 `Padding(top,…)`，别用前导撑条。
- **`Column` 的子节点沿列轴停靠时必定占满整行宽**：想在满宽栏里放一个"按内容取宽"
  的块（表格、按钮条），外面必须套一层 `Row`——`Prefer(宽,0)` 在 Column 里会被拉满。
  踩过：帮助页的公式表头蓝带被拉到页面右沿，实测 1511 对原版 1429；套 `Row` 后列宽
  按 `prefW` 取，正好等于各列宽之和。
- **手摆坐标（`DockManual()` + `Place(x,y)`）只在"普通流"容器里生效**：容器一旦
  `display:flex`，引擎的 `ArrangeFlex`/`FlexKids` 会把**每个**子节点都当 flex item，
  忽略 mx/my 并按 flex 规则缩宽——编译、运行、点击全不报错。踩过：五行修炼页
  （整页一张底图 + 叠层）给页面容器写了 `display:flex`，1117 宽的底图被压成 292、
  所有叠加挤在一行。要手摆偏移就别给容器 flex。另外 `dock==0` 的子节点尺寸来自
  `StyleWidth()/StyleHeight()`（CSS width/height，没有才用 `Prefer`），偏移点与
  尺寸要成套给。
- **部件伪类选择器（`::track`/`::fill`/`::box`…）的类串是控件自己交出去的**：解析走
  `StyleSheet.ApplyCascadeCtx` 把控件传的**类串**按空白切成类集合，所以
  `.my-widget::part` 能不能命中，取决于控件有没有把自己的 `Class` 传进去。踩过：
  `Checkbox` 传（所以 `.st-check::box` 生效），`Progress` 原来只传变体类，给进度条
  挂了用户类后 `.el-bar::track` **静默不生效**、颜色悄悄退回皮肤默认。这类"样式写了
  没反应"先查控件交出去的类串，别在 CSS 里试参数；是组件的锅就在组件里修
  （`PartCls() = 变体 + " " + Class` 两处调用点都换掉），并补一条 conformance 用例。
- **`Padding` 是从盒子自己的固定高里扣的**：给一个定高盒子加 `Padding(top,…)` 当作
  "它上面的空隙"，它会把这空隙从自身高里吃掉。踩过：设置页底部按钮行高 54 设备、
  `Padding(top,…)` 扣掉后只剩 1.5 设备，按钮被压成一条线。正确做法是在它**前面**
  放一个定高撑条（`VGap(h)` + `parent.With(gap)`）。
- **`Substring`/下标是字节不是字符**（Zan 的 `string` 是 UTF-8 字节序列）：汉字占
  3 字节，`"金币洗炼".Substring(0,2)` 会把「金」截成 2 字节的半个字——渲染成「金…」
  这种乱码，不报错。按字切要 `Substring(0, 3*n)`；跨字数运算前先想清楚单位是字节。
  踩过：铁匠铺 12 个双行功能钮全部渲染成半个字，语法/编译全过。
- **文字排版三件事**：`Label` 从盒子左缘画（`text-align` 无效，居中只能靠 flex
  容器的 `justify-content`）；`Label` 不消费 CSS 皮（`text-shadow` 描边这类效果
  复刻不了，登记为已知偏差而不是硬做）；定宽文字槽要比最长文案**留 3–5 设备余量**
  （测量与绘制是两条测量路径，刚好等宽会被省略号截成「服务器：永…」）。
- **一段正文要「自己折行」+「行内嵌彩色词」时，把折点切进数据**：`Label` 只有
  `wrap` 开关，没有富文本；`wrap=false` 时超宽是**截成省略号**而不是折行（踩过：
  规则栏 6 段正文每段只画了第一行、还带「…」，一看才发现根本没折行）。做法是
  一行一个「分段列表」（`List<段>`，每段带自己的颜色类），每行用共享的行内分段
  组件排——同一套在帮助页、铁匠铺说明、寻宝规则三处复用。参考图的断点是确定的，
  抄进数据比让引擎按宽度算更稳（字体微调不会让断点漂）；只要每行比槽宽短
  3–5 个字的余量，就不会被截。
- **尺寸单位有两套**：CSS `width/height/gap/font/padding` 是**逻辑像素**（乘 dpi
  缩放），`top/left/right/bottom` 偏移是**设备像素**。踩过：把 30 设备写成
  `height:30px` 得到 45 设备；同理"收逻辑尺寸"和"收设备尺寸"的按钮助手不能混用，
  把已乘过缩放的取值器塞进收逻辑尺寸的那个会再放大一轮（实测 10 处 1.5×）。
- **引擎缺省裁剪子节点——父盒子矮了会静默截断**。主区"舞台"不撑满内容框时只按
  子项偏好高排（实测 634 而内容框 774），挂在上面的东西只有上半截画得出来：
  记录格阵（716..875）被父容器裁到 798，格线只剩两条、底下一片空，**编译运行
  点导航全都不报错**。凡是"靠容器高决定露出多少"的内容（裁切底图、长表格），
  先确认父链每一级的盒子高（`DockFill()`/固定高），别只看自己的 `Prefer`。
- **两张同尺寸、只差颜色的素材，用像素取色定夺，别用 NCC**。踩过：`ui/00082.jpg`
  与 `ui/00083.jpg` 同为 488×249、同 12×7 格距，只差格线颜色（蓝灰 vs 棕褐），
  多尺度 NCC 只差 0.517 vs 0.585 分不出来；取原版格线像素 `(57,46,44)` 一比就
  定案。这类"孪生图"串了的症状只有颜色不对，远看一模一样。
- **空 `Src` 的 `Image` 会画 `Alt` 占位**：`Image(path, alt, fit)` 的第二参不是
  tooltip，而是 `loadState != 1` 时 `DrawPlaceholder` 画的字。踩过：格子组件为了
  "每格都有一套图标位"无条件 `new Image(artPath, "道具", …)`，空格子（`artPath`
  为空）于是在正中画出「道具」两个字——**空格的语义是「只有框」**。修在组件层：
  `artPath.Length > 0` 才挂 Image（一次修好所有调用点），别在每个调用点传空格窜
  过。凡是"图占位"组件都要问一句"空值画出来是什么"。
- **验收前先对齐坐标系，再谈偏差**：组件树 dump 的 y 常是**屏幕绝对**、像素 dump
  是**客户区相对**（差一个窗口顶偏移）；参考图与客户端**往往不是同一尺寸**——
  先在一段高信息区（导航栏两行那种）做互相关求出 `(dx,dy)` 偏移，再比其它区域。
  踩过：没做这一步时把「参考图比客户端多 47 行、客户区矮 24」误判成"页脚差 24 设备"
  的布局缺陷，白追半天。
- **素材缺失时的正确姿势**：不拿截图冒充、不自己画；用尺寸最接近的现有素材占位、
  在文档里登记缺口（"谁是错的、为什么"），并把它收进**一个函数**（`XxxArtPath()`），
  补图后只改一处。

## 同族新工具模式（参照 A 产品做 B 平台）

- UX 约定与 A 产品统一（同一套弹窗/工具条/日期筛选/右键菜单习惯），
  功能清单从 B 平台的**接口面**推导：接口分析出有哪些对象，就有哪些
  列表、哪些快捷批量操作、哪些子窗口——接口不支持的不硬造。
- 服务端中转/限流类依赖：先起本地服务 + **假数据走通全流程**（含授权、
  登录、主窗口打开的时序），再逐个换真接口。
- 外部授权等一次性流程用**临时** webview/浏览器窗口承载：只在那一步出现，
  成功即关，不做成常驻页面；授权态落本地（按账号绑定）。
- 发布物完整性：皮肤/资源/驱动随包带上——"打开全是黑的"就是漏带了。

## 图表/组件库换基准迁移（ECharts 2→5 实战沉淀）

对照基准整体升级（老基准 2.2 → 新基准 5.x 官方示例站）时的高效闭环：

- **参考源码就地快照，逐字移植**：官方示例源码批量下载成 `_scratch/ref5/<id>.js`，
  目录顺序/标题从官方注册表生成 manifest 并标注依赖（[dataZoom]/[visualMap]
  …）。option 与数据从源码提取，不凭截图/记忆猜。
- **先筛"当前可 1:1 的集合"再批量开工**：manifest 标出每例依赖的引擎缺口，
  把无缺口例按官方顺序批量移植，缺口例挂账本靠后——避免逐例卡死在半成一个
  上。目录里只放已移植条目，未移植的随批按官方位置插入；**整段清旧**，
  半新半旧的目录会让人误判完成度（用户点名："为什么不彻底清掉全换新的"）。
- **数据提取用 vm 执行，不用文本解析**：`node + vm.runInContext(code+';option;')`
  直接拿 option 对象再序列化成目标语言字面量；正则/括号匹配会抓错数组
  （markArea 排在 data 前面）。官方 `Math.random` 数据换固定种子 LCG——
  同点数同分布，截图验收才可复现。
- **逐帧重建的大数据要静态缓存**：画廊壳每帧调 Draw，≥几千点的数据生成
  一次存 static 字段，否则每帧几万次分配拖垮帧率。
- **引擎默认值差异在引擎层翻转**（splitArea 2.2 开/5.x 关之类）：字段+工厂+
  clone+JSON 解析四处一致地改，不逐例覆盖；改完跑该组件的窄测试层
  （如 `ctest -R chart`）。
- **每批同一个闭环**：移植 → 构建 → 截图（锚定自己启动的进程）→ 对照官方
  截图 → 提交（显式 pathspec）。缺口记进 docs 长期账本（如
  `docs/CHART_COMPATIBILITY_5.md`），不散落在会话里。
- **多步文本手术写脚本文件（_scratch），禁止内联 `node -e`**：bash→JS 两层
  转义会把 `\\\\n` 变成真实换行匹配，一次把几千行源文件压成一行。确定性
  重建脚本在手，出错时 git checkout 基线 + 重跑脚本即可零损失恢复。
