# RR 保存点与幂等重放

修复 MySQL/MariaDB 同键购买、保存点失败恢复或事务内查重时使用。

- 先确定外层事务是否已有一致性快照。MariaDB 10.11.14 实测：快照在业务
  SAVEPOINT 之前建立时，另一连接提交同键订单后，本连接 INSERT 报 1062，
  ROLLBACK TO SAVEPOINT 后普通 SELECT 仍返回旧的空集；FOR UPDATE 当前读
  能看到已提交订单。保存点回滚不是刷新外层事务快照的契约。
- 正常幂等查询与唯一冲突恢复都使用现有查询契约的 current read（如
  `query.inner.ForUpdate()`），复用调用方同一事务连接。不要只锁买家后再
  普通 SELECT：事务之前已建立的快照依然存在。
- 对尚不存在的订单直接 FOR UPDATE 可能令并发缺键查询持有间隙锁并互锁。
  可先锁已存在的买家行，把同买家购买串行化，再 current-read 订单；扣款仍
  保留余额条件更新。锁顺序须一致，不能另借连接或换隔离级别掩盖问题。
- 判定器要覆盖每个 caller，而非只看最终账目：独立进程/连接显式 RR，先在
  每个外层事务读空订单集，再 barrier 同时放行；每 caller 必须提交成功并
  返回同一 paid 订单，同时核对单订单、单权益、单次扣款与佣金。

证据边界：上述保存点行为由双连接原生 MariaDB 探针验证；四独立进程调用
生产 MallFlow 的同键重放已通过。此结论不代表任意隔离级别、死锁、网络断线
或提交结果不确定时都可以原事务内重试。
