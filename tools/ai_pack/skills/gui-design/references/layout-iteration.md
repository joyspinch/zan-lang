# 窗口布局迭代：从混乱到收口

> 从一次真实迭代提炼（"把网页版界面重做成原生 GUI"：117 次界面编辑、
> 20+ 条用户纠偏才收敛）。复杂窗口——标题栏+导航+内容+弹窗+动效——
> **动手前先通读本文**，能跳过其中绝大部分坑；每条都是踩过并返工过的。

## 先问框架要，不要自己造

- 复杂窗口的第一个动作是**盘点 stdlib/Gui 已有的能力**，写码前列出每块
  UI 对应的现成组件/入口。反复被用户打回的三种"自己造"：
  1. 自己给弹窗算居中（`Layer` 的模态 kind 自带居中+遮罩；只有 kind 0
     页面层需要手动定位）；
  2. 自己在应用层画标题栏按钮（`App` 的标题栏 chrome 已支持：`SetTitlebarHeight`
     加高、`SetCaptionActions` 追加功能胶囊、`SetChromeBrandIcon` 换品牌图标，
     字号/颜色走 `titlebar::brand` / `::cap` / `::action` 样式部件）；
  3. 在应用里自绘动画库已有的效果（氛围动效先查 `Gui.BackdropFx` 的 Kind
     目录，如飘带 `KindRibbon`）。
- **应用层只配置，组件层才实现**。`DllImport`/user32/命中测试/拖动协议
  属于组件与后端；应用层出现任何一样就是架构错了，返工方向是把逻辑下沉。
- 迭代中长出来的通用能力（新控件、新动效 Kind、新绘制原语）**当场提升进
  stdlib/Gui**，不要"先在应用里放着"——放着的每一天都在鼓励复制和绕过。
  （范例路径：应用内 `RibbonFx` → stdlib `Gui.Component.Ribbon` +
  `BackdropFx.KindRibbon`，同一次任务内完成。）

## 自绘/加高标题栏：三件事必须同步

只改绘制高度是"问题越修越多"的经典源头。一次改动必须同时核对三层：

1. **绘制**：栏高、背景（渐变要验证真的出来了）、标题、品牌图标。
2. **原生拖动**：后端的 caption 拖动条带高度要跟随栏高
   （Windows 上是 `WM_NCHITTEST` 返回 `HTCAPTION` 的区域），否则症状是
   "拖动窗口乱跳/拖不动"。
3. **命中测试**：自绘功能按钮排进 caption 区后，系统的拖动保护带必须按
   **实际占用像素**放宽，不能用"按钮数×按钮宽"的默认值——默认值盖住自绘
   按钮时，症状是"没有一个按钮能点"（按下被当成拖动吞掉）。

配套规则（全部踩过）：

- 系统按钮（最小化/最大化/关闭）**钉在右上角的标准条带里**：标准高度、
  默认大小、默认样式，不随品牌栏加高而放大；品牌栏其余部分保持原生拖动。
- 加高栏里悬停高亮用**按钮宽的居中圆角方块**，不要贯穿整栏的竖向色带。
- 每个 chrome 元素（品牌图标/标题/功能按钮）**独立可配**：各自的字号、
  颜色、尺寸走样式部件传入，禁止"统一大小一锅端"。
- 功能按钮与系统按钮**同一配色体系**（同一悬停/按下语义），不要两套颜色。

## 标题栏左侧的图标：默认就是程序自己的图标

Zan 的窗口是**无边框 + 自绘标题栏**（chrome），所以标题栏上看到的每个像素
都是库画的，系统那套标题栏根本不参与：

- 品牌图标默认画**程序自己的图标**（exe 内嵌的那份，编译时写进资源），
  不是占位字形。应用想换成图标库里的字形：`App.SetChromeBrandIcon("rocket")`；
  传空串恢复默认（= 程序图标）。图标大小/颜色走 `titlebar::brand` 样式部件。
- **系统窗口图标与自绘 chrome 是两套东西**：窗口类图标（任务栏、Alt+Tab、
  系统属性里看到的那个）与标题栏上画的那个**可以不一致**。用户说"标题栏
  图标不对"时先问清是哪个；改 chrome 不会改任务栏图标，反之亦然。

踩过的坑（写下这条规则时踩的）：

- **从 exe 取图标不能用 `LoadImage` + exe 路径**（`LR_LOADFROMFILE` 对 exe
  返回 0，图标组在资源段里不是文件头）：用 `ExtractIconExW` 按图标组索引取。
- **取像素必须用 BITMAPV4 头**（`BI_BITFIELDS` + alpha 掩码）：普通 32bpp
  `BI_RGB` 的 `GetDIBits` 取回来的 alpha 全是 0，图标会画成一块透明/黑方块。
- **图标圆角的 alpha 可能是 0 也可能是 1**（不同尺寸抗锯齿不同），断言
  "角上 alpha == 0"会误报；用"alpha <= 8"判"近乎透明"。
- **判"图标画出来了"要回读画布像素**（`canvas.GetPixel`），别只靠截图肉眼：
  截图看不到 alpha 全 0 的那块"画上去的透明图标"。

## 立即模式动效

- 连续动画 = **每帧自续的帧调度**：`app.RequestAnimationFrameIn(33, x, y,
  w, h)` 每帧末尾再请求下一帧，并声明脏区。只靠 hover/damage 顺带重绘的
  症状是"按住鼠标才显示"。
- 帧间隔 dt **必须钳制**：负值归 0；超过 ~100ms 按 33 处理。后台切回或
  停顿后的大 dt 是闪烁和跳变的根源。
- 氛围动效先铺不透明底色，再 `PushClip` 在自己的矩形内绘制，压不过文字；
  全画面至多一处（见 SKILL.md 克制条款）。速度/密度给可调参数，不要写死。

## 弹窗与层

- 弹窗初始尺寸**给内容留够再留余量**；"这弹窗就不能大一点吗"说明按
  控件最小尺寸算的框。
- kind 0 页面层不自动居中：打开时按**当前窗口尺寸**算一次中心（尺寸变化
  时重算或跟随），不要指望它像模态层那样自己居中。
- **居中减掉自绘标题栏**：窗口客户区高含自绘标题栏（`ContentTop`，如 48），
  拿 `ClientHeight` 直接居中会比内容区中线低半个标题栏（实证低 24 设备px，
  弹窗压住底部内容）。铺满用的遮罩同理：`ClientHeight − ContentTop`。
- **模态遮罩必须有人监听，否则不注册命中区**：`Control.FireCommon` 里
  `if (!On.Any) { return; }`（契约是"未使用的容器不能抢走画在它下面的内容
  的指针"）。空壳 Panel 当遮罩 → 点击**穿透到下层**（实证：弹窗开着点导航
  瓦片，导航被触发、弹窗被关掉）。正解是给遮罩挂一个空回调
  `block.OnClick( => { })`——只为注册命中区。**"点不动下层" = 遮罩在命中
  序列里**，不是靠不透明。
- **键事件只发给持有焦点的控件**（`Ui.KeyDownOn` 就是 `focus.IsFocused(id)`）。
  给弹窗加热键（按钮上写着 `取消(C)` 这类）要两步：`app.focus.SetFocused(控件
  .CommonId)` + `控件.OnKeyDown( => ...)`。
  **别在定时器刻度里轮询 `app.EventKind`/`EventKeyCode`**：键事件在
  `ProcessEvent` 里处理完，下一次 `PollEvent` 的 `ClearEvent` 就清了，刻度
  多半读不到（实证：`keydown 67` 之后弹窗照旧开着，改成 `OnKeyDown` 才关掉）。
- **层序冲突修层序管理，不许删组件了事**——两个层打架时干掉一个是被用户
  明确否定的方向。
- **浮层/右键菜单展开期间禁止弹出底层悬停提示（Tooltip）**：Tooltip 在帧末尾
  `Flush` 统一绘制在所有层之上。若底层组件（如表格单元格截断提示、表头提示）只靠局部标志
  判断悬停，不仅外部菜单展开时会因坐标穿透漏出提示，且右键按下当帧前置入队的提示也会直接
  盖在菜单上。底层悬停提示必须受 `!app.PointerCaptured && !app.HasOverlays` 门控，
  右键/模态展开当帧必须立即重置 tip 跟踪并调用 `Tooltip.Cancel` 撤销挂起提示。
- 阴影用 SDF 一次出图的 `Canvas.ShadowRoundRect`（四周均匀）。手叠两层
  偏移实心矩形的症状：底边一圈硬黑带、顶部没有阴影。

## 文本与图标

- 截断必须 **UTF-8 感知**：回退到非续字节边界再拼省略号；按字节截断的
  症状是侧栏信息出现乱码。
- 图标在正方形格内居中：字形尺寸按**格高的固定倍数**推（如 1.7 倍基准
  字号），不要和文本字号共用一套阶梯，也不要逐个试数。

## 子窗口（ChildWindow）与多窗口时钟

- **子窗口标题栏禁止皮肤选择与固顶操作**：`ChildWindow` 是依附主窗口的对话框/从属窗口，默认调用 `host.SetChildMode(true)`。标题栏严禁出现调色板换肤抽屉与 pin 置顶按钮，且后续调用 `EnableSkins`、`SetThemeMenu` 或 `FormBuilder.ConfigureWindow` 均必须严格锁死禁止开启。
- **多窗口动画时钟与帧泵送**：在保留模式主循环中，子窗口由 `ChildWindows.PumpAll()` 驱动。动画时钟（`animNextMs` / `fxNextMs`）到期判断必须在 `PumpAll()` 开头就地先行兑现 `ChildWindows.TickDue(now)`，且 `ChildWindow.NeedsRedraw()` 必须在动画时钟到期时立即返回 true；同时 `FoldDeadlines` 必须向主循环注册 `RequestWakeFrameAt(dl)`，确保内核定时休眠唤醒后主循环当圈即可将动画帧送达子窗口呈现，杜绝跨圈滞后或空转。

## 过程纪律（这决定快慢）

- **改一轮 → 构建 → 真实启动 → 截图 → 对照**，小步快跑；绝不连改多处
  再一次验证——出问题时分不清哪步引入。截图脚本化（杀旧实例 → 启动 →
  `PrintWindow` + `PW_RENDERFULLCONTENT` → DPI 换算 → PNG）；**截图锚定
  纪律：锚 PID、按窗口抓取**——截错窗口的像素会把你带向错误的修复。
- 布局坐标算不准时，在画面上画 **TEMP 诊断标记**（异色小块 + 关键坐标
  文本直接画进画面），一轮定位后**必须删除**。
- 修 bug 前先读组件源码弄清**既有契约**（"原来有自绘的标题栏啊，原来有
  拖动啊"）——不看契约叠补丁，是"问题越修越多"的根源。
- 用户纠偏往往是**架构信号**："为什么要写 DllImport""本身就是封装好的
  组件为什么要创造"= 该下沉进组件库的东西漏在了应用层；听到这类反馈，
  返工方向是下沉，不是继续在原地打补丁。
- 不给应用加用户没要的配置面（单皮肤应用不挂皮肤选择器）。

## 滚动容器与动态模板列表（实战血泪经验）

- **滚动条独立走廊（Overlay Scrollbar Gutter 规则）**：GUI 的滚动条为内嵌悬浮绘制（位于容器右侧内边缘 `x + w - bw - inset`）。所有声明了 `overflow-y: auto` 或 `scroll` 的列表/网格容器，**必须显式在 CSS 中预留至少 14~16px 的 `padding-right`**（如 `.items-list { overflow-y: auto; padding-right: 16px; }`）作为滑块专属走廊，严禁内容贴到容器右边缘。
  - **踩过的坑**：未预留 padding-right 或仅给 6px（小于滑块宽 8px + 边距 2px），卡片右边框、尾部开关、配置齿轮以及顶部的“编辑”按钮会被滚动条半透明滑块直接盖在上面，引发用户严重差评（"滚动条怎么可以在列表里面"）。
- **动态创建控件的 HTML 作用域样式继承（Scoped CSS 穿透）**：HTML 设计稿编译期会对 `<style>` 样式补充文档作用域类（如 `.card.zs-app`）。当后台 Zan 代码使用 `new Element()` 动态创建模板行（如 `CreateProtectRow`）并挂入 DOM 时，容器必须在 `Adopt`（`AddKid`）阶段将父级的 `zs-*` 作用域类自动下传注入给动态子节点整棵子树。
  - **踩过的坑**：动态创建的节点缺少作用域类，导致 `.protect-row-card.zs-app` 等 CSS 规则完全无法命中，直接回退到无样式的 `display: block`。这导致原本 Flex 水平横排的图标、文字、开关垂直向下堆叠，文字在 54px 的固定行高内被挤出容器外不可见，表现为"文字丢失、组件乱跳"的灵异现象。
- **`overflow: hidden` 严禁伪装为滚动容器**：`overflow: hidden`（mode 1）不是滚动容器。主轴溢出计算时，只有 `overflow: auto/scroll`（mode >= 2）才保持自然尺寸供滚动；`overflow: hidden` 容器的子元素必须按 `flex-shrink` 正常收缩适配视口。否则父级高度无法正确约束子列表，导致外层全屏泄露全高滚动条。
- **保留模式滚动平移（ShiftTree）必须连带平移行内文本坐标（elRuns）**：GUI 滚动容器（`UpdateScroll`）在 `Arrange` 尾段对整棵子树下发 `ShiftTree(dx, dy)`，平移所有后代控件的 `bx/by` 绝对坐标。`Element` 派生类接管了行内文本流（`elRuns`），记录了行盒绝对定位坐标 `(r.x, r.topY)`。`ShiftTree` 必须为虚方法且 `Element` 必须重写 `ShiftTree` 联动平移 `elRuns` 中所有文本 run 的 `x` 与 `topY`。
  - **踩过的坑**：若 `ShiftTree` 未重写平移 `elRuns`，容器滚动时卡片与普通控件外框下移/上移，而卡片内的文本 run 仍留在原始未滚动绝对坐标。随后外框的 `PushClip` 裁剪矩形移走，文本直接被裁掉或脱离卡片位置，表现为“向下滚动了，组件没变，组件里面的内容跑了……”。
- **现代桌面滚动条美学：极细 4px 悬浮胶囊轨与局部独立滚动架构**：
  - **4px 极细胶囊与静止透明轨道**：现代桌面 UI 滚动条滑块宽度应收敛至 4px，未拖拽/未悬停时轨道背景必须为 `transparent`，严禁在页面右侧常驻绘制贯穿全高的实心粗灰柱。滑块配色采用半透明低对比度中性灰（`rgba(180, 184, 192, 0.45)`），悬停时再平滑加深。
  - **局部滚动隔离（固定快捷操作区，仅列表滚动）**：Dashboard 或工具箱类页面中，顶部的快捷操作/常用工具栏必须作为 `flex-shrink: 0` 的固定顶层区域驻留，严禁将全页包入同一个大滚动容器内导致快捷入口被滚走。只有下方的分类软件/服务列表（如系统工具、网络工具）包裹在独立的 `overflow-y: auto` 滚动容器中。
  - **视口容量精确对齐**：标准分类列表（如 7 项核心防护项）在基准视口内必须精确规划卡片行高（如 50px）与间距（8px），使其刚好完整舒展在视口内，严禁因几像素误差导致原本可完全容纳的列表多出无意义的“幽灵滚动条”。
- **白底现代扁平与 2.5D 纯净融合纪律**：
  - 严禁将带环境背景的矩形位图硬贴在白底页面上形成生硬截断面。
  - 严禁在主视觉下方堆砌循环切换的跑马灯/轮播状态文本胶囊，破坏界面的克制与纯净感。
  - 选中态采用精致的 1px 细橙线框（`#ffd8b3`）与微投影，替代突兀的实心深橙色大色块，确保全套图标、字号与内边距在 1:1 设备像素下呈现出生产级软件的呼吸感与工整度。

- **行内标签与内边距边框（排版盒模型纪律）**：
  - **严禁对行内标签（`span`）直接应用带有边框/圆角/背景的高亮胶囊样式**：在 HTML/CSS 流式排版中，`span` 默认走行内文本流（`elRuns`），其渲染边框或背景包围盒与字流 run 的起点计算往往出现偏差，导致"文字脱离选区、紧贴甚至溢出边框"的严重位移。具有宽高、内边距（padding）、背景和边框的选项胶囊必须明确声明为块级或弹性盒（如 `div` 或 `display: flex; align-items: center;`），并显式定义行高（`line-height`）与盒模型（`box-sizing: border-box;`）。
- **组件样式隔离与尺寸继承冲突（图标按钮解耦规则）**：
  - **严禁在卡片内部套用顶层导航或固定尺寸的复合按钮类名**：如在 38x38px 的卡片图标容器（`.tool-item-icon`）内部直接实例化套用了 `.nav-btn`（默认 40x40px 且带边框），会导致子级溢出并挤压同级文字容器，造成图标偏位、边框杂色与文本截断。卡片内的图标应使用无边框、无默认 padding 的专用纯净类（如 `.tool-icon-btn`），并通过 `Prefer(24, 24)` 约束真实绘制尺寸，由父级 Flex 容器统一进行居中对齐。
- **网格式卡片高度统一与垂直居中纪律**：
  - **并排排列的实体卡片与占位槽（如常用工具卡片与"拖拽到此"虚线槽）必须严格统一物理高度（如 72px）**，并在 CSS 与代码中显式声明 `height`、`min-height`、`box-sizing: border-box;` 以及 `display: flex; flex-direction: column; align-items: center; justify-content: center;`。严禁随意使用不对称的纵向 padding 导致卡片内部图标偏向顶部或文本沉底。
- **拖拽交互的视觉连贯性与即时跟随**：
  - **凡支持拖拽到落区的操作，必须提供实时跟随光标的拖拽代理（Drag Avatar）**：在鼠标按下或拖拽开始的当帧，通过每帧输入钩子（`FrameHook`）立即将带有图标、标题和半透明投影的浮层锚定到光标中心，同时改变落区的视觉反馈（虚线流动跑马灯/吸附就绪状态），杜绝“不知道拽没拽起、不知道拖到哪里”的盲操作。
- **保留模式 GUI 中拖拽跟随代理（Drag Avatar）的动态位移排版与事件门禁纪律**：
  - **严禁仅对悬浮图层直接赋值外框绝对坐标（如 `dragAvatar.bx = x; dragAvatar.by = y;`）而省略调用 `Arrange`**：直接赋值容器外框坐标不会递归平移内部子控件（如图标按钮与文本标签）的局部相对坐标，导致子控件滞留在 `(0, 0)` 原点或被裁剪溢出，呈现为“跟随图层空白或不显示”。必须在每帧动态跟随钩子（如 `FrameHook`）中显式调用 `dragAvatar.Arrange(curX, curY, curW, curH)`，触发 Flex 递归排版，确保内部图标与文本每帧同步锚定在光标正中。
  - **拖拽卡片严禁仅监听 `OnClick`**：用户按住拖动（Drag）时指针产生连续位移，系统判定非轻击，`OnClick` 永远不会触发。必须通过 `OnMouseDown` 捕获按下起点，同时为卡片内部子元素配置 `pointer-events: none;` 防止内部图标/文字拦截事件。
  - **松手判定（`!app.pointerDown`）必须设置持续帧门禁（如 `dragTick >= 3`）**：防止首帧因输入采样抖动或单击松开瞬间误判为松手，导致跟随图层瞬间销毁闪退。
  - **拖拽代理（Drag Avatar）避开指针热点纪律**：跟随代理必须放置在光标右下方的自然偏移位置（如 `(mx + 12, my + 12)`），保持鼠标物理箭头尖端裸露无遮挡。严禁将代理卡片正中对齐到光标尖端（如 `mx - 65, my - 21`），否则跟随图层会挡在光标物理坐标与底层落区之间，导致 HitTest 命中被浮层拦截，落区无法感应 Hover 与释放。
  - **拖拽释放原生点击互斥与位移阈值状态机纪律**：
    - **点击与拖拽必须完全解耦**：卡片或项目的 `OnClick` 仅用于执行本体点击业务（如启动对应工具），**绝对禁止在 `OnClick` 中调用 `StartDragTool` 唤起悬浮代理**。若在 `OnClick` 中起拖，拖拽松手或轻点时伴随派发的点击事件会反复重新创建悬浮代理，导致光标上永久黏附幽灵卡片（用户反馈“放手之后多出来别的图标”的致命 bug）。
    - **4px 移动位移阈值判定**：在 `OnMouseDown` 时仅记录按下意图、起点坐标 `(dragStartX, dragStartY)` 与待拖拽目标对象，不可立即显示浮层；必须在输入循环或每帧钩子中比对实际移动距离 `abs(dx) >= 4 || abs(dy) >= 4`，超阈值才正式激活 `StartDragTool`。若在此之前已松手，直接降级为普通点击。
    - **复合卡片事件全子树覆盖（命中叶子穿透问题）**：GUI 的 HitTest 默认命中几何最内层的叶子节点（如卡片内的标题、说明文本 `span` 或图标容器）。当外层卡片作为可拖拽/可点击实体时，必须将手势动作委托同步绑定到所有子节点，杜绝用户点击/按下文字或说明区域时光标命中未绑定事件的叶子控件导致拖拽或点击无响应。
    - **时间窗口防抖阻断**：卡片与落区的 `OnClick` 必须增加时间窗口防抖阻断（如 `now - lastDragEndMs < 400ms`），杜绝刚松手入槽瞬间被残余 Click 再次反向激活拖拽。
