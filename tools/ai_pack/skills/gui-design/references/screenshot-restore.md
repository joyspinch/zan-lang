# 截图还原布局与交互体验基线

适用：用户给一张现有程序/网页截图，要求"照这个做 / 严格还原布局 /
复刻这个界面"，或者要求"让界面体验好一点"但说不清具体改什么。
分工：`app-migration` skill 管**程序级**复刻（映射账本、行为语义对齐）；
本文件管**单屏界面级**——一张截图到可编译、可验收的布局。审美档位
（字号/间距/高度阶梯）在 SKILL.md 主干，这里只讲"怎么把截图变成结构"。

## 0. 四条铁律

1. **几何忠实**：区块划分、从属关系、对齐线、比例、密度必须与截图
   一致。用户说"严格还原"时，结构自由度为零。
2. **语义提升**：量到的像素换算成档位（4 的倍数间距、阶梯字号/高度、
   token 颜色），不逐像素照抄——但换算不得改变视觉结构。截图里同排
   同类的控件尺寸不一致（AI 生成稿常见），还原时**归一到等宽/同高**，
   这叫修正不是走样。
3. **颜色字体走主题 token**；只有用户点名"同款配色"才从截图抽精确
   色值，并在交付说明里列出色板出处。
4. **文案一字不改**：语言、大小写、标点、占位数据都照抄截图。

## 1. 测量转写（先量后写，禁止边看边猜）

1. **定设计尺寸**：截图像素 ÷ DPI 倍数 = 设计像素。**倍数不许拍脑袋**，
   按下节"三票定倍数"用证据定；后续一切数字用设计像素。
2. **从外到内切区块，一次一刀**：标题栏 → 侧栏/导航 → 内容边距 →
   头部行 → 区块序列 → 状态条。每块记 x/y/w/h。
3. **块内再切**：行结构、列结构、卡片网格（数列数、量列距）、按钮组。
4. **控件清单**：类型 / 文案 / 状态（主次、禁用、选中、危险）/ 对齐
   （数字列右对齐？标签左对齐？）。
5. **产出布局账本**——还原的唯一依据，交付时逐行对账：

   | 区块 | 截图物理px | 倍数 | 设计px | 原语映射 + token |
   |---|---|---|---|---|
   | 侧栏 | 372 | 1.5 | 248 | Dock(3) → Prefer(230,0) 取整 |
   | 指标行列距 | 16 | 1.5 | 11 | Grid.Of(4).Gap(12) 归档 |

   **账本必须带"物理px"与"倍数"两列**：换算只发生在账本里一次，
   之后全程只用设计值。中途心算折算就是混乱的起点。

## 1.5 DPI 与缩放：还原混乱的最大来源

截图还原的翻车十有八九是单位错了：把 150% 截图里的 372px 当逻辑值
写进代码（还原窗口在 100% 下侧栏宽出一半），或者把 100% 截图当 150%
折算（整体瘦一圈对不上原图）。三个环节各有铁律：

**(a) 分析侧——三票定倍数**。标准控件的逻辑尺寸是公开的常量，拿截图
里三个独立证据量物理值，除以候选倍数（1 / 1.25 / 1.5 / 2）后**落回
逻辑档**的那个就是答案，三票取多数：

| 证据 | 逻辑尺寸(设计px) | 100% | 125% | 150% | 200% |
|---|---|---|---|---|---|
| 正文/菜单字号 | 12–16 | 12–16 | 15–20 | 18–24 | 24–32 |
| 按钮/输入框高度 | 28–32 | 28–32 | 35–40 | 42–48 | 56–64 |
| 窗口标题栏 | ~32 | ~32 | 40 | 48 | 64 |
| 间距步进 | 4 的倍数 | 4 | 5 | 6 | 8 |

Model Router 截图实测：正文 ~24px、按钮高 ~46px、标题栏 ~44px——
三者都只有 ÷1.5 才落档（16 字号 / 30 高 / 30 标题栏），判 150%，
一票都不用猜。**间距步进是隐藏第四票**：截图里量到的间隙若老是 6 的
倍数而不是 4 的，倍数基本就是 1.5。

**(b) 还原侧——代码里只写逻辑值**。设计像素进代码的形式只有三种：
档位 token（Gap/字号/高度类）、语义尺寸（`Prefer(230,0)` 这类取整后
的容器宽高）、按内容量的高度（Flex/Grid/Card 不写高度）。禁止把截图
物理像素原样抄进代码——框架在运行时会按用户 DPI 再缩放一次（见
SKILL.md"缩放纪律"的样式路径/自绘路径两分法），抄物理值 = 双重缩放。
审计红旗：**代码里出现账本"物理px"列的原值（372、46 这类），必查**。

**(c) 对拍侧——先归一再叠加**。原图和还原窗的截图各自可能在不同
倍数下截取：对拍前把两边都除以各自倍数归一到设计尺寸（或都放大到
同一物理倍数），再并排/50% 叠加。两张物理尺寸不同的图直接叠，差出来的
"偏差"全是倍数差。窗口物理尺寸 ≠ 设计尺寸时，比较的是**比例关系**
（侧栏宽 ÷ 窗宽、卡片高 ÷ 行高），不是像素绝对值。

## 1.6 取整与半像素节距：账本算得对，落码差几像素

账本里的设计值经过 `Px()`（`v * dpi / 100`，整数除法）落成设备像素，
**凡是非整数结果都会被截断**，一页几十行的列表会把这个误差累积成看得见的
偏移。三条实证（表格页还原踩出来的）：

- **行节距 49.5 设备**（行高 45 + 缝 4.5）：`Px(30)=45`、`Px(3)=4`，节距只有
  49，12 行后短 6 设备。原图自己也在 49/50 之间交替（行顶 214/263/313/362…
  是交替的）——用 `RowHAt(r) = 行高 + (r % 2)` 复现原图的交替，别指望把
  `.5` 四舍五入救回来。
- **容器 padding-bottom 量不到就不写**：原图末行与容器底边的距离如果没量出来，
  拿 `Padding(bottom)` 猜一个值会顶不到位（实证末行落 802，原图 809..811）。
  改成在容器内容里显式塞一条撑条行（`Prefer(0, 底距)`），位置才是量出来的。
- **同一层叠加的偏差会互相抵消**：单看某一行的 ±3 设备是噪声，看**首行顶、
  末行底、节距**三个锚点——首末都对上才算节距对，只对首行说明后面在漂移。

## 1.7 还原前先查原引擎的控件清单

参照物是**另一个引擎/产品**时（不是同级 Gui 截图），先把它自己的控件清单
翻出来当第一手依据，再决定用什么实现：

- 原引擎文档里**列了控件、但这个移植/工具链里没有**的（实证：DM3 UI 规格
  `docs/arpg/03-UI控件与皮肤系统.md` 有 `bagBox`/`itemBox`/`skillBox`/
  `quickBox` 一族格子控件，`stdlib/Game/Arpg` 只移植了数据模型与
  label/button/imageBox/progressBar 等基础控件，**格子类没移植**）——
  **不要自绘**（违反"控件自己负责绘制"），也**不要凭空给标准库造一个新
  公开接口**（违反"以复用现有为荣"）。正确动作：用**项目内已有的共享组件**
  兑现同一职责（实证 legend 的 `src/Slots.zan` 是背包/掉落/装备环/宝石/技能
  格共用的格子组件，表格再抽 `src/TableUi.zan`），并把清单对照结论写进
  还原账本，避免下一个人重新查一遍。
- 原引擎里**有对应 stdlib 组件**的（分页、Tab、表格）坚决用组件，不手搓：
  组件默认样式偏大时用**皮肤规则压回原图尺寸**（实证 `pagination { height: 20;
  font-size: 12; }`），而不是回去自己画一排页码按钮。
- 但**组件不等于原控件**：形态差异要**登记为已知偏差**，不能为了像素回去
  手搓，也不能假装没差。实证：`pagination` 的 `simple` 档是「上一页 +
  可编辑当前页输入框 + 散排的 `/ N`」，原版是**一个框里写 `1/13`**；同一
  参考图里原版自己的页脚右组位置还各页不同（1218..1480 vs 1212..1456），
  都不是还原方的漂移。写进账本，别按某一页去"修"另一页。
- 组件的**分部件样式要写到部件上**：字号取 `pagination::arrow` 而不是
  `pagination`，只在父级写会落主题默认档（实证「上一页」宽 19 设备）。
- 原引擎的**列表选中态/焦点框**通常有专用图（实证 `00132/00134.png`
  735×30 通用选中条），别用半透明色块顶替。

## 1.8 图里认不出的字形/小图标：点阵化 + 候选渲染对齐，别肉眼猜

参考图里的小元素（徽章上的字、图标里的符号）常只有十几设备像素，肉眼
只能看出"一团笔画"。**猜一个相近的字写进代码，错字会一直留到成品**。

做法（实证：图鉴/行会那枚红椭圆等级徽章的铭文）：

1. **二值化打点阵**：把该区域按亮度阈值（`>150`）打成 `#`/`.` 的 ASCII
   矩阵，笔画结构一眼可读——徽章是「左二（上短下长横）+ 右十（竖贯中横）」，
   不是数字。
2. **候选渲染对齐**：用系统字体把候选字（含两字组合）按目标字形高度渲染，
   与点阵算 IoU / 归一化相关，取结构吻合者（`二十` IoU 0.353，且逐笔对得上；
   纯 IoU 排名会混进生僻字，必须回看结构）。
3. **交叉验证语义**：`二十` = 行会等级上限 20，与同行「限制等级 20 级」
   自洽；再确认 12 行的徽章**逐像素相同**（是图标位而非逐行数据），
   从而确定它是常量而不是数据列。
4. 把结论（"是图标位 / 铭文是什么"）写进账本，别留"以后再看看"。

## 1.9 从裁切图推坐标：两条框架契约先算进去

参考图是**某个容器/弹窗本体的裁切**（裁切原点落在它的边框上）时，账本里量到的
坐标不能直接进 `Place()`——先减掉框架自己的两条度量，否则整窗每一项整齐偏 1~2px，
看起来像"字体/边框差"，其实是坐标原点差（实证：一个 377×335 的模态弹窗，第一条
按"裁切 − 2"存，每一项都偏 1 设备px）。

- **手摆子项的原点是父的 border 内侧**。`dock 0` + `Place(x,y)` 的落点是
  `bx + inset`（`Control.Arrange` → `ArrangePositioned`）。所以
  **`Spec` = 裁切值 − 该侧边框厚**。定位方法：写一条 `Place(0,0)` 的探针 dump
  出来看它实际落在父的哪一像素，别推。
- **边框厚度要量不要按 CSS 值换算**：`border: 1`（逻辑）在本机 150% 下渲染成
  **1 设备px**（实测框线只占一列/一行），不是 1.5——参考图的框线是 1.5 设备px
  跨在两列上被 JPEG 抹开，量化后天然差 ≤1 设备px，**别为这 1px 去凑坐标**。
  写大一号（`border:2`）是整框胖一圈，更错。
- **文字项的账本值给"字盒顶"，不是墨顶**：量出参考图的**墨心**，再用本版
  Label 的度量化回去（实测盒高 20 时墨心 = 盒顶 + 10.5，多行同值），
  即 `盒顶 = 墨心 − 11.5`；改字号/盒高要重算这条。
- **盒宽按本版字体给，不照抄原版墨宽**：原版墨宽 58 的字串，本版字体可能要
  84 设备px，照抄会被 `Label` 省略号截断（实证显示成「祝福语..」）。宁可把盒
  加宽到压住相邻控件左缘（墨没压到就行），并给该子控件 `NoOverlapCheck()`——
  **豁免必须挂在子控件上**：布局 lint 的 `CheckOverlapKids` 读的是
  `a.overlapExempt`（a = 子），挂父容器不生效。


## 2. 原语映射决策树

- 通栏横条（顶部工具区/底部状态条）→ `Dock(1)`/`Dock(2)` + `Prefer(0,h)`
- 通栏竖条（侧栏/导航）→ `Dock(3)`/`Dock(4)` + `Prefer(w,0)`
- 其余内容区 → `Dock(5)`，内部按截图结构选：
  - 纵向堆叠的区块 → `Panel.Column().Gap(档)`
  - 一行多物（不等宽、工具行）→ `Panel.Row()` / `Flex`；左右两端对齐
    （左标题右按钮）→ `Flex.Row().Between().AlignCenter()`
  - 等宽卡片行/指标行 → `Grid.Of(n)`（**n 从截图里数出来**）
  - 左列表右详情（1:1 或 1:2）→ `Panel.Row()` 两子 `Grow()`，不要用
    两个 `Dock(5)`（会互相叠）
  - 表单 → `FormBuilder` 或标签列固定宽的 `Panel.Row`
  - 可滚动内容 → `ScrollView`/`ScrollColumn`
  - 弹层/抽屉 → `OverlayPopup`/`Layer`
- 手摆 `mx/my` 坐标在还原里**永远不出现**——截图是像素的，但还原产物
  必须是结构的，这样窗口缩放才不散。

## 3. 写码纪律

- 区块顺序、从属、可见对齐线与账本一致；区块标题与内容左缘共线。
- 截图里按钮/卡片的高度、内边距不量入代码——走主题默认（同档），这是
  铁律 2 的"修正"。
- 占位数据照抄截图（"请求 0 · 输入 0"就写这个字符串），让对拍时图文
  可直接对照。
- **共享组件的几何只能有一份**。同一族页面里出现"某列不是文字"（格子换成
  徽章/按钮/图标）时，别在页面里另写一套行骨架：把行拆成**行骨架**
  （行类/行高/列缝/左右内缩）+ **造格子的 helper**（文字格/自定义子盒格/
  操作钮格），页面只负责拼格子列表（实证：共享表格把 `TblRowCls` 改成
  `TblRowBoxes(cells, r, rowCls)` 的薄封装，`TblCellCls/TblCellBox/
  TblActionCell` 供页面自选）。否则列缝、行高的半像素补偿会在两份代码里
  各自漂移，对拍时表现为"两页对不上"。

## 4. 验证闭环（缺一步都不算还原）

1. 编译通过；`ZAN_GUI_OVERLAP=1` 跑一遍，`gui-overlap` 命中必须 0
   （环境变量用法见 SKILL.md"排版原语纪律"节）。
2. 以账本的设计尺寸起窗，按截图锚定规范（锚 PID、
   按窗口截）截图，**记下截图机的 DPI 倍数**。
3. 两边先按各自倍数归一到设计尺寸（见 1.5(c)），再并排/50% 叠加：
   区块边界误差 ≤ 半档间距、对齐线不歪、比例关系保持、文案全同。
4. 有偏差 → 改账本对应行 → 重截。小步收口，不做大面积重写。

## 5. 交互体验基线（还原/新写收尾都过一遍）

布局对了只是及格；下面每条都是"用户用起来顺不顺"：

**反馈闭环**
- 每个提交动作都有下文：进行中有 Spin/loading 文案，成功有 Toast，
  失败有具体错误 + 重试，绝不静默。
- 长操作进行中按钮禁用（防重复提交），完成后恢复。

**防呆**
- 破坏性操作（删除/停止/覆盖）二次确认，确认按钮用 danger 类，
  不与常用按钮贴邻。
- 表单必填/格式错误就地标出（红字在字段下），不在提交时才总报错。

**键盘与焦点**
- 表单 Enter 提交；弹窗 Esc 关闭；Tab 顺序 = 视觉顺序。

**状态完整**
- 空态用 Empty + 一句引导（"暂无模型映射——到模型映射页添加"）；
  错误态给具体原因；禁用态给原因（tooltip）。

**信息排版**
- 主按钮唯一且在最右/最下；数字列右对齐；同类列表行高一致。
- 导航当前项有选中态，页标题与导航项同名；文案动词具体
  （"启动代理"不是"确定"），全程同名。

## 6. 实战示例：Model Router 截图 → 布局账本 → 结构代码

**定倍数（三票）**：截图 1794×1198 物理。正文 ~24px（→16 落档）、
按钮高 ~46px（→30 落档）、标题栏 ~44px（→30 落档）——三票全指 1.5，
设计尺寸 ≈1196×798。账本（节选，换算只在账本里发生）：

| 区块 | 物理px | 倍数 | 设计px | 原语映射 + token |
|---|---|---|---|---|
| 侧栏（品牌+菜单+底部网关态） | 372 | 1.5 | 248 | Dock(3) → Prefer(230,0)；内部 brand Dock(1)/menu Dock(5)/状态 Dock(2) |
| 头行：眉题+标题 左，刷新/更多 右 | 高 66 | 1.5 | 44 | Flex.Row().Between().AlignCenter()；高度按内容 |
| 指标行：4 张等宽卡 | 列距 16 | 1.5 | 11 | Grid.Of(4).Gap(12) 归档 |
| 双栏：实时路由 \| 快速控制 | 1:1 | — | — | Panel.Row 两 Card Grow() |
| 用量统计通栏卡 | 高 ~220 | 1.5 | ~146 | Card 进内容列末行；高度按内容 |

（截图原稿的巨型刷新钮、被裁的"…"、宽窄不齐的指标卡是原生成 AI 手摆
的病，还原时按铁律 2 归一——结构位置不变，尺寸回档位。）

还原代码骨架（已验证：编译通过，1200×800 下 Arrange 重叠命中 0）：

```zan
Panel root = new Panel();
Panel side = Panel.Column();                       // 侧栏
side.Dock(3).Prefer(230, 0);
Panel brand = Panel.Column(); brand.Dock(1);       // 品牌:名+副题
Panel menu  = Panel.Column(); menu.Dock(5);        // 菜单项逐行 With
Panel gw    = Panel.Column(); gw.Dock(2);          // 底部网关状态
side.With(brand); side.With(menu); side.With(gw);
root.With(side);

Panel content = Panel.Column().Gap(12);            // 内容列
content.Dock(5).Pad(4);
Flex head = Flex.Row().Between().AlignCenter();    // 头行
head.With(左标题列).With(右侧按钮行);
content.With(head);
Grid metrics = Grid.Of(4).Gap(12);                 // 指标行:四张等宽卡
metrics.With(MetricCard("本地代理", "运行中"));     // …×4
content.With(metrics);
Panel mid = Panel.Row().Gap(12);                   // 双栏 1:1
```
