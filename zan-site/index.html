BEFORE YOU BUILD

开始之前，把几个问题说清楚。

语言怎么选、应用怎么交付、遇到问题找谁。先了解边界，再开始你的项目。

Zan 是 C#，可以直接使用 .NET 的包吗？

Zan 是独立语言，采用熟悉的 C# 风格语法，使用自己的标准库、包与 LLVM 原生工具链。它不运行在 CLR 上，也不能把 .NET / NuGet 接口直接当作 Zan API。

认识语言与兼容边界 →
自己的应用可以商用和分发吗？

当前维护源码的 ZCSL 包含运行时与输出例外，允许商业化和分发自己的应用。工具链的修改与再分发另有条款，扩展包和第三方依赖也有各自许可；请核对实际下载版本所附的许可文件。

查看许可与应用分发 →
原生编译意味着所有应用都只需要一个文件吗？

程序无需 JVM 或 .NET CLR，但仍包含 Zan 运行时支持。GUI、音频、图像或外部库可能需要配套原生驱动和资源，交付前应检查发布目录并在目标系统运行验证。

了解编译与发布 →
有目标平台名称，就代表所有能力都可用吗？

编译目标、运行时、GUI 后端和安装打包是不同层面的能力。应结合平台说明、应用所用的包和目标设备验证结果判断，不把交叉编译成功等同于完整实机支持。

查看各平台支持状态 →
遇到安装、编译或运行问题，怎样反馈？

先查看快速开始的排错说明。反馈时附上 SDK 版本、操作系统、最小复现代码和完整错误信息，说明预期行为与实际结果，便于定位问题。
