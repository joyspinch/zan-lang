# 内存、别名与资源生命周期

当前实现说明，按仓库源码与测试核实于 **2026-11-11**。已安装 SDK 可能与此仓库状态不同。Zan 使用自动引用计数 ARC 管理受管理引用对象；原生资源、循环引用和非拥有视图仍需要明确的生命周期设计。

## 先区分三件事

| 问题 | 需要关注的对象 | 主要机制 |
| --- | --- | --- |
| 存储何时回收 | 类、数组、字符串、闭包等 | ARC 的保留与释放 |
| 外部资源何时关闭 | 文件、套接字、线程同步句柄等 | `Dispose`、`Close`、资源特定协议 |
| 某个访问是否仍有效 | 弱引用、视图、原生地址与回调 | 强引用持有关系、地址所有权与同步 |

这三者有关联，但不能互相替代。对象存储被回收不等于任意外部句柄已经关闭；一个地址仍非零也不等于它仍然有效。

## ARC 的基本规则

编译器在引用的保存、传递和离开作用域等位置生成相应的保留与释放。最后一个强引用释放后，对象的受管理存储可以回收，其拥有的引用也相应释放。

普通业务代码不手动给类实例执行 `retain` 或 `release`。应通过变量、字段、容器和清理协议表达所有权。

对象可以因字段、容器元素、闭包或正在执行的异步帧而继续存活。把一个局部变量赋为 `null` 只撤销该位置的引用，不会保证没有其他位置继续持有它。

ARC 不是全堆追踪式 GC。它不会定期寻找所有不可达对象并自动拆开任意强引用环，也不能消除分配、引用计数和释放链的执行成本。

## 值复制与引用共享

结构体的普通赋值复制值，类和集合的赋值复制引用。复制引用后，两个变量指向同一份对象状态。

以下是方法体片段，形状由 `cs_list_aliasing.zan` 覆盖。

```zan-fragment
List<int> first = new List<int>();
first.Add(1);
List<int> second = first;
second.Add(2);
Console.WriteLine(first.Count);
```

上面的计数为 2。`List<T>`、`Dictionary<K,V>` 和数组都没有写时复制模式；经某个别名执行的增删或元素写入，会被其他别名观察到。

需要独立容器时，应显式创建并复制元素。即使容器独立，若元素是类引用，它们仍可能指向同一对象。真正的深复制要由领域模型定义复制到哪一层。

`string` 不可变，多个变量可以安全共享同一文本内容；一次拼接产生的字符串值不会原地改写此前的字符串内容。

## 结构体中的引用与容器槽

结构体不一定只包含数值。含字符串、数组或类字段的结构体在复制时，仍须保留这些字段的引用关系，因此不能笼统宣称“所有结构体都没有 ARC 工作”。

当前实现区分结构体局部副本与直接容器槽写入。

| 形状 | 效果 |
| --- | --- |
| `Point copy = items[i]` 后修改 `copy.X` | 修改局部副本，原槽不随之改变 |
| `items[i].X = 42` | 当前实现直接修改列表或数组中对应结构体槽的字段 |
| 将结构体存入两个不同槽 | 两个结构体值独立，内部引用字段仍可能共享对象 |

直接字段写入有 `list_struct_field_assign.zan` 回归覆盖。旧版本中“下标字段赋值总是只改临时副本”的经验不能当作当前语义。

跨原生边界复制含引用字段的结构体是另一回事。它涉及 ARC 和 ABI，不应当作普通字节缓冲区进行随意覆盖，见[原生互操作](interop.md)。

## 空引用与可空值

引用类型允许 `null`。这表示没有对象，而不是一个拥有默认字段的空对象。

对于可能返回 `null` 的调用，当前检查器会拒绝部分直接成员访问链。清楚的写法是先保存结果、检查为空，再访问成员，或使用适当的 `?.` 和 `??`。

检查器的保护不等于任意代码路径都有完整的非空证明。外部输入、弱引用变化、并发修改和原生返回值仍需要由调用者处理。

`int?` 等可空值类型携带有值状态，与类引用的空值不是同一种表示。读取 `.Value` 前应确认 `.HasValue`，或者选择明确的回退值。

## 强引用环与弱引用

若父对象强持有子对象，子对象又强持有父对象，即使业务代码已经放弃这组对象，环内部仍可能维持非零引用计数。

`weak` 表达“不拥有目标”的关系。弱字段不会阻止目标释放；目标失效后，弱关系可以被观察为空。

以下是类型声明片段，来自 `weak_field_lifecycle.zan` 的形状。

```zan-fragment
class Node {
    public int Tag;
    public weak Node Parent;
}
```

读取弱关系后，应先取得局部强引用并检查，再进行一组操作。这样一组操作使用的是同一个已获取的对象，而不是反复读取可能变化的弱字段。

弱引用通常适合父指针、观察者、缓存提示或回调的宿主关系。它不替代“谁拥有谁”的设计，也不保证跨线程的一连串读写自动成为原子操作。

编译诊断和循环检测可以帮助发现问题，但不能将“没有警告”理解为整张对象图绝对没有环。

## 闭包、事件与长期持有

闭包需要在定义它的方法返回后继续使用数据，因此会保留捕获项或相应共享单元。实例方法组也需要保持接收对象的有效性。

常见的强引用环是：对象保存一个委托字段，委托又捕获该对象；另一个形状是父对象拥有子控件，子控件的事件处理器强捕获父对象。

可行的生命周期策略包括以下几种。

- 在所属会话或窗口结束时解除订阅并清空回调。
- 让回调持有独立的状态对象，避免再强持有宿主。
- 用明确的弱关系取得宿主，调用前检查它是否仍然存活。
- 为订阅或注册返回可关闭的对象，由调用方保存并释放。

把状态移到静态字段只会把持有时间延长到进程级，不会自动解决环或资源清理。

## 资源释放与 using

Zan 不支持用户析构器 `~Type()`。编译器会拒绝声明，因为 ARC 的对象释放路径没有用户析构钩子。

需要确定性清理时，应使用类型提供的 `Dispose()`、`Close()` 或对应的专用释放函数。`IDisposable` 与 `using` 可以将释放绑定到一个明确作用域。

下面是类型和方法体两个片段，依据 `cs_b02_using.zan`。

```zan-fragment
class Resource : IDisposable {
    public void Dispose() {
        Console.WriteLine("disposed");
    }
}
```

```zan-fragment
using (Resource resource = new Resource()) {
    Console.WriteLine("working");
}
```

`using` 的释放路径覆盖正常离开以及异常离开。资源必须真正提供适合该语法的释放协议；仅仅把某个方法命名为 `Close`，不代表所有 `using` 形状都会自动调用它。

对于只提供专用关闭方法的资源，使用 `try` / `finally` 明确配对。资源关闭以后，即便对象仍有其他别名，其方法也可能已经不可用。

设计自己的资源类时，应说明重复关闭是否允许、关闭后的调用如何失败，以及是否仍有异步操作或回调持有它。

## 原生缓冲区与非拥有视图

`NativeMemory.Alloc` 返回 `nint` 地址，需要与 `NativeMemory.Free` 配对。它不因局部整数变量离开作用域而自动释放。

`Span<T>`、`ReadOnlySpan<T>` 和字符串视图提供对现有存储的访问方式，不能单凭视图值还在就认定底层存储仍在。

对视图和原生地址应明确以下信息。

- 底层存储由谁分配，由谁释放。
- 可访问的长度与元素宽度是多少。
- 源对象是否可能被释放、扩容、替换或关闭。
- 视图是否会逃逸到回调、返回值或异步等待之后。
- 是否有其他线程或别名同时修改同一内存。

特别是从临时字符串取得非拥有视图后再保留它，可能让视图超过源字符串寿命。零复制意味着共享原有存储，不能把它当作独立副本。

## 异步与并发中的寿命

挂起的异步方法会把需要继续使用的局部状态保存在状态机帧中。等待本身不会让正在使用的受管理局部对象立即释放。

取消采用协作式观察点，并与清理路径配合；不能依靠“发出取消请求”立即释放正在使用的缓冲区或关闭仍在进行 I/O 的句柄。

引用计数正确并不等于共享对象的字段访问安全。两个 worker 同时修改集合或状态，仍需锁、原子操作、消息传递或明确的单一拥有者协议。

任务返回、任务结果被消费、订阅关闭与资源关闭可能发生在不同时间。设计这些关系时，应参考[异步与并发](async.md)的任务形状与结果交接规则。

## 观测与诊断

`--check-leaks` 用于启用运行时泄漏诊断，相关调试与运行参数见[工具链](tooling.md)。应检查真实退出路径，而不仅是构造成功的路径。

`System.GC` 提供分配量、内存估算、循环检测与快照等观测入口。名称兼容常见习惯，但它没有把 Zan 变成追踪式 GC 语言。

当前 `GC.Collect()` 的方法体调用内存修剪，尝试归还可释放的物理内存；它不是空操作，也不是“自动清除全部引用环”。`GC.DetectCycles()` 提供循环诊断，不能把检测等同于回收。

验证资源管理时，至少覆盖正常结束、异常结束、取消以及回调仍在途的情况。读数变化要结合容器缓存、分配器缓存和仍被业务持有的对象解释。
