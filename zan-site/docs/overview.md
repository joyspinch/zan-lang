# Zan 语言概览

当前实现说明，按仓库源码与测试核实于 **2026-11-11**。已安装 SDK 可能早于或不同于本文对应的仓库状态；遇到差异，应先确认编译器版本、标准库和包的来源。

Zan 是静态类型、提前编译的编程语言。主编译器 `zanc` 将源程序经过 LLVM 编译为目标平台机器码，引用对象使用自动引用计数 ARC 管理。

语法与 C# 有许多相似之处，包括类、结构体、接口、属性、泛型、委托、异常与 `async`/`await`。这种相似性方便阅读，但不意味着 Zan 使用 .NET 运行时，也不意味着任意 C# 程序可以原样编译。

## 编译器、运行时和库的分工

Zan 程序由语言机制、运行时服务和库代码共同组成。区分这三层，有助于定位功能与问题。

| 层次 | 负责的内容 | 仓库中的主要位置 |
| --- | --- | --- |
| 编译器 | 解析、类型检查、泛型实例化、LLVM 代码生成 | `src/compiler/` |
| 核心运行时 | ARC、异常支持、线程与协程调度、基础 I/O | `src/runtime/` |
| 标准库 | 源码形式的通用类型和系统接口 | `stdlib/` |
| 扩展包 | GUI、网络、数据、游戏等可复用能力 | `packages/` |
| 原生驱动 | 图形、音频等平台接口的实现 | `src/drivers/` |
| 开发工具 | 语言服务、调试适配、格式化和文档工具 | `src/lsp/`、`src/dap/`、`src/fmt/`、`src/doc/` |

有些常用类型由编译器直接提供，例如 `string` 的成员、`List<T>`、`Dictionary<K,V>` 和 `Task`。只搜索 `.zan` 标准库文件，不能证明一个 API 不存在；还应查看 `src/compiler/builtin_api.c`。

另一方面，类型出现在仓库里不代表当前工程已经引用它。应核对命名空间、包位置、编译输入与 SDK 版本。

## 程序如何运行

一个普通控制台程序以类型中的静态 `Main` 方法作为入口。可以返回 `void`，也可以返回表示退出状态的 `int`；命令行参数可通过 `string[] args` 接收。

编译链大致分为源文件解析、名字绑定、类型检查、生成 LLVM IR、目标代码生成与链接。最终程序包含所需运行时支持；具体动态库依赖取决于程序使用的功能和目标平台。

多文件程序需要把工程源文件纳入编译输入。`using` 是命名空间导入，不应理解为“自动编译当前目录里全部业务文件”。工具链如何收集源码、定位包与发布资源，见[工具链](tooling.md)。

静态字段初始化器与静态构造器在进入 `Main` 之前执行。它们不是 C# 中以首次访问为触发点的惰性类型初始化。

## 类型与抽象能力

基础数值类型区分宽度：`int` 为 32 位，`long` 为 64 位；`float` 为 32 位，`double` 为 64 位。`decimal` 使用独立的 128 位十进制表示。

结构体与枚举具有值语义；类、数组和集合通常由引用共享。赋值一个集合变量不会复制集合内容，也没有写时复制模式。

类型系统提供以下组合方式。

- 类支持单继承、多个接口、虚方法和重写。
- 结构体适合组合具有值语义的数据，也可实现接口。
- 泛型类型与泛型方法保留参数、字段和返回值的类型关系。
- 委托、方法组和 lambda 用于回调；捕获状态的闭包也参与生命周期管理。
- 元组用于组合多个值，模式匹配用于类型判断与分支选择。
- 属性、索引器、运算符重载、记录类型和扩展方法提供常用表达方式。

这些能力有各自的适用边界。约束检查、装箱范围、迭代器限制等应读[类型系统](types.md)与[语言基础](language.md)，不要按另一门语言的同名功能推断全部行为。

## 文本模型

源文件采用 UTF-8。运行时 `string` 是不可变 UTF-8 字符串，`Length` 和索引按字节计算。

例如 `"中文".Length` 为 6，而不是 2。一个字节下标可能落在多字节字符内部；用户看到的字符数和屏幕宽度也不是字节长度。

`char` 表示 Unicode 码点，在当前主编译器中占 8 字节。它既不是 UTF-8 的单个字节，也不是 C# 的 16 位 UTF-16 码元。

处理文本时应区分字节、码点、字素簇与显示宽度。网络协议需要字节长度，光标移动和排版则往往需要更高层的文本处理。

## 内存与资源模型

ARC 由编译器插入保留和释放操作。对象最后一个强引用释放后，其受管理存储可以回收；这不需要周期性的追踪式垃圾回收。

ARC 仍有成本，也不会自动解决所有资源问题。循环强引用可能使对象存活，闭包和事件订阅也可能延长对象寿命。`weak` 可用于表达不拥有对方的关系。

文件、套接字、原生句柄和原生缓冲区有自己的关闭协议。需要显式调用 `Close`、`Dispose`，或使用合适的 `using` 作用域。用户析构器 `~Type()` 不受支持，声明会被编译器拒绝。

原生地址与零复制视图是额外的责任边界：ARC 不会替外部缓冲区延长有效期，也不会验证任意地址。具体规则见[内存与资源](memory.md)。

## 异步与并发模型

`async` 方法被转换为可挂起和恢复的状态机。`await` 表达等待关系；它不是“每调用一次就创建一个操作系统线程”。

当前受支持的原生 64 位目标默认使用多 worker 协程调度器。任务可能在不同 worker 上恢复，不能依靠单线程假设保护共享可变数据。

直接等待异步方法、用 `Task.Run` 保留结果，以及用 `Task.Spawn` 启动分离任务，是三种不同用法。特别是 `Spawn` 不把返回值和异常交给等待句柄的调用方。

库还提供通道、门、原子量、锁与取消令牌。取消是协作式协议，令牌必须沿业务调用链明确传递。详细类型与调度规则见[异步与并发](async.md)。

## 与熟悉的 C# 写法对照

| 主题 | Zan 当前行为 |
| --- | --- |
| 运行环境 | 原生 AOT 与 Zan 运行时，不依赖 CLR 来执行语言对象模型 |
| 字符串索引 | UTF-8 字节索引，不是 UTF-16 码元索引 |
| 成员可见性 | 未标修饰符的成员默认公开 |
| 静态初始化 | 进入 `Main` 前执行 |
| 语句 `switch` | 非空分支末尾隐式退出，只有连续空标签共享分支 |
| 对象清理 | ARC 加显式资源协议，没有用户析构钩子 |
| 集合赋值 | 共享同一集合，写入可被其他别名观察 |
| 同步方法内 `await` | 部分目标可同步驱动，要求协程帧的目标会被拒绝 |

这张表用于提醒需要核对的语义，不代表完整兼容性清单。迁移代码时，应保留原程序的行为测试，并逐个核对 API 签名、错误处理和资源所有权。

## 平台与互操作

编译器目标、运行时后端、系统 SDK 和具体包支持是不同维度。某目标能生成代码，不等于它拥有桌面 GUI、同一种网络后端或完全相同的动态库加载方式。

使用 `[DllImport]` 声明原生函数时，需要匹配参数宽度、返回值、调用约定、结构体布局和所有权。外部字符串和回调不能只按语言表面类型判断寿命。

跨平台工程应把系统差异集中在明确的边界中，使用实际目标的条件编译符号，并在对应环境核对行为。见[原生互操作](interop.md)和[平台支持](platforms.md)。

## 阅读源码和与 AI 协作

遇到文档、历史经验与实现不一致时，优先寻找当前实现与针对性测试。规范文件是索引，但个别章节可能落后于实现。

1. 先确定问题属于语法、编译器内建、标准库、包还是平台驱动。
2. 找到类型声明和真实方法签名，再寻找同形状的用例。
3. 记录输入、预期输出、退出状态以及涉及的 SDK 版本。
4. 把完整程序与声明片段分开，不能把片段直接当作可运行工程。
5. 对跨平台、异步或原生边界，增加实际目标上的行为证据。

本网站的 `zan` 代码块用于完整程序；`zan-fragment` 用于已明确标注的局部代码或声明片段。片段需要放入适当的类型、方法或工程上下文。
