# .zform 声明式条件键：代价评估

结论先说：**A 档（真值键，无表达式语言）值得做，B 档（v-if 级表达式）不值得。**
两档的分界不是工作量，而是「要不要在 `.zform` 里养一门表达式语言」。

---

## 一、为什么 A 档便宜：条件的通路已经存在

`.zform` 的 `bind` 已经有一条现成的每帧同步通路：宿主在每帧前把状态实体的值推入控件，帧后再把用户改动写回。

- `ChildWindow.SyncFromNode()` — 每帧递归整棵树，对 `c.bindPath != ""` 的节点执行 `model.PathGet(path)`（stdlib/Gui/ChildWindow.zan:126-147）
- 状态实体就是一个 `JsonValue`，支持 `PathGet` / `PathSet`（同文件 31、83 行 `Mount(root, model)`）
- 隐藏本身也已经免费：`Control.SetShown(false)`（stdlib/Gui/Control.zan:660）后 `StyleVisible()` 会让布局与命中测试自动跳过该节点（Control.zan:925、988、1058），**不会留下空洞**

也就是说，A 档的核心逻辑就是在 `SyncFromNode` 里多一句：把 `showIf` 指向的状态路径取出来判真值，然后 `SetShown`。真正的成本不在这里，在下面那张往返表。

## 三、必须先定夺的语义空洞（这才是真风险）

### 3.1 隐藏的必填字段会无声地挡住提交
`GenForm` 在编译期把每个 `required` 字段的校验语句直接展开进 `__ValidateForm()`（GenForm.zan:272-284、511-513），**不看运行时可见性**。一个被条件隐藏的必填字段会让 `__ValidateForm()` 永远返回 false，而用户在界面上看不到任何红框 —— 提交按钮就是死的，且极难排查。
必须定：隐藏 ⇒ 跳过校验（在发射的校验语句里加 `StyleVisible()` 守卫），还是隐藏 ⇒ 仍然校验（那就得同时定义错误怎么呈现）。**这条不定，A 档不能动手。**

### 3.2 没有状态实体时怎么办
`model` 只在 `ChildWindow.Mount(root, model)` 时挂上，允许为 null。`showIf` 求不出值时必须有确定行为：默认**显示**（宁可多显示也不要整块界面凭空消失），并且这个 fallback 要写进文档，否则 AI 会以为默认隐藏。

### 3.3 设计器画布上不能真的隐藏
`FormBuilder` 同时服务运行时和设计器预览。若设计态也按条件隐藏，被隐藏的控件在画布上消失、无法选中、也就无法再改它的条件 —— 死锁。设计态必须忽略 `showIf`（可加淡显/角标提示），这需要 `FormBuilder` 有一个设计态开关。

### 3.4 制表符格式是位置编码，只能追加在末尾
`Serialize` 的行格式没有版本号，靠尾部 `if (fi < f.Count)` 逐段向前兼容（Serialize.zan:158-179）。新列必须**加在 `class` 之后**；插在 `class` 之前会让所有旧文档把类名读成条件字符串，且不报错。

## 四、B 档（v-if 级表达式）额外要付什么

A 档只支持「一个状态路径的真值」。一旦要 `role == "admin" && !locked` 这类表达式，就要额外背上：

1. **一门新语言**：词法、语法、优先级、类型强制（`JsonValue` 是 string/num/bool 混合）、错误信息与出错行列 —— 而且它跟 Zan 本身的表达式语义必然会慢慢分叉，两套真相。
2. **求值时机**：每帧对整棵树求值，还要处理表达式里引用不存在路径、除零、类型不匹配等运行时错误怎么报（界面上没有地方报错）。
3. **设计器可视化编辑**：条件从「选一个绑定变量」变成「写一段代码」，Inspector 要么退化成裸文本框（那就不再是设计器），要么做条件构建器 UI。
4. **知识层**：`zform.json` 得描述表达式语法，静态解析器（`ZformSchema`）也得能校验它，否则 AI 又开始猜。
5. **长期维护**：每加一种运算符都要同步 5 个落点 + 测试。

对照一下现在的替代品：同样的逻辑在 code-behind 里是三行普通 Zan 代码，有编译器检查、有 IDE 补全、有断点。**B 档是花两三倍的工程量，换一个比宿主语言更弱、更难调的子语言。**

## 五、工作量与建议

| 方案 | 工作量 | 长期负担 |
|---|---|---|
| A 档（`showIf` 真值键 + 设计器往返 + 范例文档） | 约 1 个会话 | 低：一个键，语义封闭 |
| B 档（表达式语言） | 约 2-3 个会话，且落地后仍会持续回流 | 高：等于自建一个模板引擎 |
| 只补范例（不动格式） | 约半个会话 | 无 |

建议：
1. 先把 3.1 那条语义定下来（隐藏是否跳过必填校验）；
2. 做 A 档，键名建议 `showIf`（配 `hideIf` 是糖，可不做），语义严格限定为「状态路径真值」；
3. 不做 B 档；真正复杂的条件走 code-behind 或代码模式 —— 那边的 `if` 是真语言的 `if`。
