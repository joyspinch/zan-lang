# await 公共消费尾段与聚合帧修复（2026-10-08）

普通子任务 await 的立即完成和恢复路径改为先合并子帧句柄，随后共享异常检查、结果解码与子帧释放。冻结 OnePlus 输入的隔离对照稳定减少 **32,791 条 resume 指令（5.98%）**和 **8,205 个基本块**。

两边均包含本轮聚合值与嵌套字段的正确性修复；这一对照只切换普通 await 消费尾段。四次均成功静态发布，输入及原生依赖散列保持不变。

## 正确性修复

- 局部帧扫描原来排除 LLVM struct。三 long 结构体的 awaited 结果首次读取正确，再 Yield 后变成零或随机值。现在聚合局部和捕获单元均进入帧规划，类型化 proxy 最终替换为帧字段地址。
- 含字符串、对象、数组等强引用字段的值结构体沿用逐字段所有权：持久前缀唯一拥有，别名赋值和初始化捕获字段；ramp retain by-value 参数，借用返回 retain 字段；完成、放弃和丢弃结果释放字段。清槽跳过逃逸 cell 的 payload。
- 嵌套字段赋值原来先把中间结构体读成 LLVM 聚合，然后 pointer-only 分支静默不发射 store。最小 `outer.inner.value = 17` 探针在挂起前就读回零，修改前编译器同样失败。现在递归解析原存储地址，复用于 ref 字段参数，保留引用字段 capture。

这些修复的成本在隔离基线与合并后完全一致。它们使本轮 resume 基线变为 548,536，而首轮为 548,521；不能将这 15 条差异计入尾段收益。
