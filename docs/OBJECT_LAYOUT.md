# 对象头压缩：16+8 → 8 字节（设计提案）

> **状态**：进行中（2026-11-24）。只涉及 C 宿主 zanc 的对象/字符串 ABI；自举后端
> （`src/selfhost/irgen`）有自己的 24 字节对象头与 32 字节串头，不受影响。
> 落地后按 WORKSPACE_CONVENTIONS 附录 §7 并入 `zan-compiler-internals` skill 并删除本文。

## 1. 问题

两个指针字段的类 `class Node { Node l, r; }` 每个实例 40 字节：

```
[-16] u32 空位 | [-12] u32 rc | [-8] u64 描述符指针(或 --check-leaks 站点号) | [+0] vptr | [+8] l | [+16] r
```

C 的同构节点 16 字节，binary-trees 峰值 43 MB 对 18 MB。冗余有两处：

1. **vptr 槽**：类一律在 +0 留指针位（为了基类/派生类字段下标一致），可像 `Node`
   这样整条继承树既无虚方法也无接口的类，槽里永远是 null。
2. **头里的 8 字节描述符指针 + 4 字节空位**：描述符（析构函数、祖先名表、反射记录、
   字段走图）是"每个运行时类型一份"的只读数据，用 32 位下标就能找到。

## 2. 新布局

```
对象：  [-8] u32 rc | [-4] u32 tw        （头 8 字节，块基址 = p-8）
        tw = bit 31 栈上提升 | bit 30 对象标记 | bit 29 前垫 8 字节 | 站点号（bit 0..28）
        [+0] vptr —— 仅当所在继承树有多态（虚/抽象/覆写方法或接口）时才有
字符串：[-12] u32 len | [-8] u32 rc | [-4] u32 "ZANS"   （头仍 12 字节，len 与 rc 互换）
数组：  不变（[-32] i64 rc | [-24] magic | [-16] count | [-8] magic、秩或数组描述符指针）
```

不变量：

- **rc 一律在 [-8]**（u32，`ZAN_RC_OFF`），对象与字符串同址同宽，通用 retain/release
  仍不必分辨种类；`0xffffffff` = immortal。
- **[-8] 的 u64 仍是"头字"**：对象 = `(tw<<32)|rc`，字符串 = `("ZANS"<<32)|rc`。
  "高 32 位 == ZANS 即字符串""头字 < 0 即栈对象"两条旧判定照旧成立。
- **对象标记**让头字互不混淆：数组头字里的描述符指针高 32 位 < 0x8000（用户态
  地址），秩 < 4096，都没有这一位；"ZANS"与数组魔数有这一位，但解出的站点号
  （0x1a41xxxx）远超任何程序的站点数，按表长比界即查不中。`release_dyn` 的数组
  判定（头字 == magic 或 1..4095）也不会误中对象。
- **站点号 → 描述符**：默认模式新增 `__zan_desc_tbl[站点号]`（0 号为 null，
  `zan_hdr_desc`）；`--check-leaks` 模式本来就按站点号查各张站点表，只是站点号
  从 [-8] 的 i64 挪到 tw。C 运行时（泄漏报告、GC 走图）在默认模式下经
  `zan_rt_register_desc_table`（main 入口登记）查描述符。表在 irgen 收尾、反射成员
  表压缩之前定型——描述符只经这张表被引用。
- **对齐 16 的类**（i128/decimal、16 字节向量字段）：头 8 字节后 p 只保证 8 对齐，
  这类实例在块前多垫 8 字节（站点实参带 `ZAN_OBJ_TW_PAD16`），p = 块 + 16，释放时
  按 tw 的这一位传 p-16。栈上提升对象一律放在 16 对齐 alloca 的 +16。
- **字符串长度挪到 [-12]**（u32，`ZAN_STR_LEN_OFF`，`zan_str_len_ptr`）；
  `ZAN_STR_LEN_UNKNOWN` 照旧表示"超 32 位，回退 strlen"。静态字面量写成两个 i64：
  `ZAN_STR_LIT_W0(len) = len<<32 | 0xffffffff`（首 4 字节填充写全 1，分片常量 blob
  据此识别）、`ZAN_STR_LIT_W1 = ("ZANS"<<32)|0xffffffff`。
- **vptr 槽按继承树决定**：`class_vptr_offset` 对"树根（最上层非 object 祖先）的
  所有后代里有任一多态类"的类返回 1，否则 0（计划由 `class_vptr_plan_compute` 在
  注册任何类布局前扫全部类型声明算出；`ZAN_VPTR_ALWAYS=1` 退回一律留槽）。zanc 是
  整程序编译器，基类与派生类仍对同一字段给出同一下标。按首字比对身份的分派
  （接口分派、object.ToString 候选链）只会在有 vptr 的对象上命中；无 vptr 对象的
  首字是字段值，不可能等于某张 vtable 的地址，走兜底分支。
- **--arc-guard 隔离**：释放点（返回地址）低 32 位记在 [-4]（[-8] 是失效标记）。
- **软失败 scratch 前缀不变**：P-8 仍是 `ZAN_ARRAY_MAGIC`，其低半当 rc 读出极大值、
  高半解出越界站点号。

## 3. 代价

- 读描述符多一次查表（`release_dyn`、`is/as`、`GetType`、泄漏/GC 走图），都不在
  分配/retain/release 快路径上；虚调用不变（vptr 仍在 +0）。
- 字符串长度探测多一次 4 字节读（长度在 [-12]、标签在 [-4]，同一缓存行）。
- 跨映像（两个 Zan 动态库互传对象）时站点号只在各自映像内有效——与此前描述符
  指针可跨映像不同；当前没有这种用法，记作限制。

## 4. 落地顺序

1. vptr 槽按继承树条件化（Node 40 → 32 字节）。
2. 字符串 rc/len 互换 + 对象头 8 字节 + tw=站点号（C 运行时、embed、优化器栈提升、
   分片常量 blob 同步）（Node 32 → 24 字节）。
3. 量 `_scratch/bench_suite`（trees 目标 ≤ 1.6× C 内存，时间不退）。
