# AI 辅助开发基础设施——通用方案

> 定位：这是**方案**，不是现状清单。它规定"让智能体在 Zan 生态里高效、正确地
> 干活"的设施应该长什么样——用角色、契约和不变量表达，不绑定任何一刻的文件
> 清单。此刻每个角色由哪些文件/工具承担（会漂移，仅示例），见
> [ai-assist.md](ai-assist.md)、[AI_ONBOARDING.md](AI_ONBOARDING.md)、
> [MCP_HOSTING.md](MCP_HOSTING.md)、[agent-kb/](agent-kb/README.md)。
> 现状变了，本方案不变；与方案冲突时，改现状而不是改方案。

方案覆盖两种状态，且两种状态**只有坐标系不同，没有设计不同**：

| 状态 | 坐标系根 | 典型消费者 |
| --- | --- | --- |
| 开发态（现在） | zan-lang 仓库根 | 在本仓库干活的所有智能体会话（多个并行） |
| 发布态（以后） | 用户项目根 / SDK 安装根 | 用户项目里的 AI 客户端（Claude Code、Cursor、Copilot、Devin…） |

同一套契约，换根即换状态。把发布态假设（安装路径、冻结的工具目录、多租户
托管）写进开发态设施，或者反过来，都是违例。

## 0. 六条设计原则（这就是"通用性"的全部含义）

1. **事实不手写。** 一切会随代码漂移的事实——符号与签名、控件清单、模板清单、
   示例目录、路由表、测试覆盖、文档覆盖——由扫描器从仓库生成。手写的只有
   方法论、约定与判断依据。手写事实就是造第二份真相，必然漂移。
2. **路径即契约，内容可再生。** 客户端（任何客户端）可以依赖的只有少数**固定
   路径的入口**；入口的内容必须能由一条命令再生。演进方式是改内容不改路径、
   加能力不改客户端。
3. **规约即数据。** 能自动执行的规约——测试层级怎么选、哪些测试互斥、提交前
   查什么——写成机器可读的规则表。人读的文档引用表或由表生成，而不是各写
   一套散文；脚本、AI、IDE、CI 用同一份规则。
4. **一个事实库，N 个访问通道。** MCP 工具、纯文件产物、IDE 面板是同一事实库
   的三个视图。给任何通道加功能之前先问：事实库里有没有？没有就加扫描器，
   不在通道里加特判。
5. **时效可判定。** 每个生成产物带输入戳（编译器指纹 + 输入清单摘要）。访问方
   读到过期产物必须能发现——报"过期"或自动刷新——不允许静默用旧账。
6. **能力自描述。** 控件、模板、示例、技能都自带清单（PropSpec、manifest、
   front-matter）；目录 = 全部清单的并集。新能力入库即自动可见，目录代码
   零改动。

## 1. 分层与角色

| 层 | 职责 | 不变量 | 角色的现状映射（会漂移，仅示例） |
| --- | --- | --- | --- |
| 事实层 | 从仓库抽取结构化事实 | 只读源码、可再生、带输入戳 | 仓库结构索引器、单元/路由索引器、知识生成器，产物集中在一个派生目录 |
| 知识层 | 方法论与约定 | 方法论手写；事实只引用不复制；引用写"怎么重新找到"，不写行号 | agent-kb、SPEC/STDLIB、stdlib `///` 文档 |
| 访问层 | 把事实与知识交给智能体 | 根目录内 confinement、鉴权、三通道同源 | MCP 服务、固定路径的生成入口文件、IDE 面板 |
| 验证层 | 改动 → 证明对 | 按路径选层级、串行互斥调度、结构化结果 | 测试三层标签、测试脚本、构建门禁 |
| 规约层 | 行为边界 | 一份源、多端安装（模板化，不 per-client fork） | AGENTS.md、WORKSPACE_CONVENTIONS、技能包 |

## 2. 入口契约（客户端无关，路径固定、内容再生）

任何智能体拿到项目，依赖的入口有且只有三类：

1. **规约入口**：仓库/项目根的 `AGENTS.md`——手写、短，写规矩和指针，
   不写事实。
2. **生成索引入口**：一个固定路径的机器/人可读清单（llms.txt 风格），内容由
   事实管线生成：项目是什么、怎么编、怎么测、事实库在哪、有哪些能力与技能。
   不手写，手工编辑会在下次再生时被覆盖——这是特性不是缺陷。
3. **服务入口**：MCP 连接时的 `start_here`，返回与 1、2 同源的信息加工具目录。

三处**同源**：2 和 3 从事实库 + 规约片段拼装，1 指向 2。一致性能被脚本校验。
反例：三处各手写一份"怎么构建"，改了一处忘另外两处。

## 3. 事实管线（生成、戳、刷新）

- **扫描器按事实域划分**：符号、控件、模板、示例、路由、测试映射、文档覆盖，
  每域一个扫描器，各自可独立重跑。
- **产物集中在一个派生目录**（git-ignored，随时可再生），每份产物头部带
  输入戳：生成器指纹 + 输入清单摘要。
- **一条命令全量刷新**，子命令按域刷新；结构改动后（新增/移动/改签名）由
  会话自律刷新，访问层在读产物前验戳兜底。
- **验收标准（通用）**：改任意被索引的事实 → 一条命令 → 三个通道一致看到；
  故意不刷新 → 访问层能判"过期"。

## 4. 验证回路

- **规则表**：路径模式 → 层级/命令 → 互斥组。互斥是真实约束（如共享同一个
  编译器产物时测试不能并发构建），必须进表，不靠记忆。
- **执行器**：按表选层级、串行调度互斥组、输出结构化结果（JSON：用例、状态、
  诊断 file:line:col、日志指针）。
- **dry-run**：只报"将跑什么"，供人/AI/IDE 在动手前预估成本。
- **失败回喂**：诊断直接可进下一次请求的上下文。
- 同一个执行器服务四种调用方：开发者命令行、提交前门禁、AI 会话、IDE 面板。
  只做一份，不做四个。

## 5. 规约的机器可执行化（提交前检查）

把"能自动检查的规约"清单化：根目录无杂物、临时产物只在 `_scratch/`、新诊断
有正反两个用例、改模板跑了对应 e2e、生成产物未过期。输出逐项通过/失败与
修复建议。同一份清单挂三个挂点：脚本（人）、MCP 工具（AI）、面板（IDE）。

## 6. 技能服务化

技能 = 文件（正文 + front-matter 一行摘要）。通道按需取：直读文件的客户端走
固定路径，MCP 客户端走 `skills_list` / `skill_read`。写法规约：技能只写方法论
与流程；事实一律指向事实库，不内嵌快照——否则技能变成第二份事实。

## 7. 开发态专项（本仓库，现在）

- **本仓库自己是第一个"用户项目"。** 设施先在开发态长出来并被日常会话使用，
  发布态只是把同一批产物换个根打包。凡是"等发布再做"的部分，开发态一定
  用不上，发布时也一定是错的。
- **并发会话纪律即设施的一部分**：提交是会话间唯一同步点；互斥资源（编译器
  产物、测试运行）在规则表里登记；在途文件归属另一会话时不碰。
- agent-kb 的自维护规则照旧：方法论手写、事实抽取、引用自愈。

## 8. 路线图（承接 agent-kb/gaps.md 的优先级）

每项给通用落地形式与验收标准；"现状由谁承担"不在本表。

| 优先级 | 项 | 落地形式 | 验收标准 |
| --- | --- | --- | --- |
| P1 | 事实管线统一 | 戳 + 一条命令刷新 + 过期判定 | 见 §3 验收 |
| P1 | 三入口同源 | 生成索引入口 + start_here 拼装 + 一致性校验脚本 | 校验脚本长期绿 |
| P1 | 验证回路 | 规则表 + dry-run + 结构化输出（§4） | 给定改动路径列表，dry-run 正确预测层级；真实跑输出 JSON |
| P2 | 能力目录 | 清单并集（控件/模板/示例/技能）+ manifest 增加能力维度（网络/数据库/WebView/HMI/串口…） | 新增能力不改目录代码即可见；勾选能力 → 依赖与起步代码自动注入 |
| P2 | 影响范围查询 | 事实库上的图查询：定义/引用/继承者/覆盖测试/描述文档 | 任意符号一条查询产出 impact[]，覆盖测试不漏 |
| P2 | 任务状态 schema | 项目内可持久化、可续跑、可回溯的任务对象 | 会话中断后新会话可从文件恢复计划与验证记录 |
| P2 | UI 端到端用例集 | 驱动脚本 + 基线截图库 + 阈值比对，机制不绑定具体面板 | "建项目→选模板→编译→运行→截图比对"可重复、无头可跑 |
| P3 | 诊断知识回流 | 从诊断正反例自动聚合"错误码 → 根因 → 修法 → 回归"库 | 按编译错误消息可检索到已知案例 |
| P3 | 帮助反馈聚合 | 本地诊断聚合 + 与知识库案例互链 | 上报协议落地时无需改事实库 |

排序理由不变：先降"猜"的成本（能力目录、影响范围），再堵"能编过就说完成"
（验证回路），然后补证据链最薄的 UI e2e。

## 9. 反模式（出现即返工）

- 手写目录、清单、工具表，或文档里贴签名快照。
- 双份事实：任何"同一事实在两处各有一份"的结构。
- 客户端特定 fork：为某个客户端单独改规约或复制一份规则。
- 发布态假设泄漏进开发态：安装路径、冻结目录、多租户托管写进开发设施。
- 文档引用写行号：写"怎么重新找到"（grep 关键字、函数名）。
- 把"IDE 里有面板"当设施前置条件：先脚本 + 产物 + MCP，面板复用同一管线。
