# IDE 内置知识库与知识图谱（设计）

> 定位：**IDE 内置功能，不是外部脚本。** 事实层由 IDE 从代码里抽取和校验，
> 人只写方法论（本目录其它文档）。目标是让智能体和人都能问出：
> "这个能力已经有了吗？在哪？谁在用？还有效吗？哪些是垃圾可以清了？"

## 为什么不能只靠手写文档

手写的清单（有哪些控件、哪些模板、哪些主题 token）**一定会过期**，过期的知识比没有
知识更糟——它会让智能体自信地写出错的代码。所以分三层：

| 层 | 内容 | 谁维护 | 过期怎么办 |
| --- | --- | --- | --- |
| L1 方法论 | 怎么思考、怎么定位、怎么验证、约定与禁令 | 人 | 很少变；变了手改 |
| L2 事实索引 | 符号、引用、模板、主题 token、测试、文档、控件能力 | **IDE 自动抽取** | 增量刷新；带时间戳与来源 |
| L3 图谱视图 | 脑图/图谱展示、筛选、跳转、清理候选 | IDE 面板 | 从 L2 实时生成 |

## L2：事实索引的数据来源

全部来自"已经存在的产出"，不新造解析器：

| 来源 | 提供的事实 |
| --- | --- |
| `src/lsp` 符号索引 | 命名空间/类/成员/函数的定义位置、签名、引用 |
| 编译器（`zanc`）诊断与 IR 阶段 | 类型关系、继承、调用、未使用符号候选 |
| `zandoc`（`src/doc`） | 文档注释、公开 API 说明 |
| `templates/**/template.manifest` | 模板清单及其结构化元数据（type/target/category/size/sketch…） |
| `CMakeLists.txt` + `tests/` | 测试清单、层级标签、每个测试覆盖的源文件 |
| `stdlib/Gui/Theme.zan`、`skins/` | 主题 token 全集 |
| `stdlib/Gui/Widget`、`Component`、`Hmi` + `PropSpec`/`ControlFactory` | 控件能力目录（可用属性、能否被设计器摆放） |
| `docs/**` | 文档章节及它描述的符号 |
| 项目树 + `zan.proj` | 项目结构、入口、目标平台 |

## 图模型

**节点类型**：`File` `Namespace` `Class/Struct` `Function/Member` `Template` `Control`
`ThemeToken` `Test` `DocSection` `Project`

每个节点带：
- 来源（文件 + 行范围）
- 稳定 id（命名空间全名 / 相对路径 + 符号名）
- 最后一次校验时间与校验方式（"由 LSP 索引确认"/"由测试通过确认"）
- 状态：`fresh` / `stale`（源文件更新但未重索引）/ `missing`（源里已不存在）

**关系类型**：`defines` `references` `calls` `inherits` `implements`
`template_includes`（模板复制/引用了某文件或控件）`test_covers` `doc_describes`
`theme_uses`（控件用了哪些 token）

## L3：面板交互（脑图式）

- **搜索优先**：输入 `Gauge` 立刻定位节点，展开一跳邻居（谁定义它、谁引用它、哪个测试
  覆盖它、哪个文档写了它、哪个模板用了它）。
- **筛选**：按类型（只看控件 / 只看模板 / 只看测试）、按模块（`stdlib/Gui` 子树）、
  按状态（只看 `stale`/`missing`）。
- **跳转**：任意节点双击打开源码定位；关系边可显示"引用点列表"。
- **增量刷新**：保存文件后只重算受影响子图；全量重建作为显式命令。
- **视图**：
  - 能力目录视图（面向智能体：有哪些控件/模板/库可用，怎么用，示例在哪）
  - 依赖视图（模块之间谁依赖谁，找循环依赖）
  - 覆盖视图（哪些公开符号没有任何测试覆盖）
  - 清理视图（见下）

## 清理：只给候选和证据，不自动删

代码库里确实有大量无用产物（试验 exe、失效文档、被替换的控件、重复模板）。但
"没人引用"≠"可以删"。清理视图给出**候选 + 证据**，删除必须人确认：

**候选规则**

| 候选 | 判据 |
| --- | --- |
| 孤立符号 | 无 `references`、无 `test_covers`、非导出、非入口 |
| 失效文档 | `doc_describes` 指向 `missing` 节点 |
| 失效主题引用 | 控件引用了不存在的 token（现在是编译错误，历史文档里仍可能有） |
| 重复模板 | 模板树内容近似 + manifest 仅尺寸类字段不同（就是 gui-phone/tablet/desktop 那次） |
| 陈旧临时产物 | `_scratch/`、`build/` 中久未使用的文件 |
| 缺失清单文件 | manifest 声明的 `entry`/`preview` 文件不存在 |

**必须排除在"无引用即可删"之外**（否则会删掉活代码）：

- 程序入口（`Main`）、导出符号（DLL 导出、ABI）
- 反射/字符串注册的调用点（`HandlerRegistry`、`ControlFactory`、路由表、组件扫描产物）
- 模板里的源文件（它们被"复制"使用，不被"引用"）
- 测试/示例专用代码
- 平台条件编译分支（`#if WINDOWS/MACOS/...`）

**展示的证据**：为什么被判为候选、最后一次被引用/修改的时间、同名符号是否在别处存在、
删除后可能影响的节点列表。

## 落地阶段

1. **P1 只读索引 + 搜索**：接 LSP 符号索引与 manifest/测试/文档扫描，做出能力目录视图。
   收益立刻可见（智能体"有没有现成的"从猜变成查）。
2. **P2 图谱面板**：节点/关系可视化、筛选、跳转、增量刷新、状态标记。
3. **P3 覆盖与清理视图**：候选 + 证据 + 人工确认后的批量操作（走正常编辑/删除路径，
   可撤销）。
4. **P4 与任务闭环打通**：任务的"影响范围""能力匹配"直接由图谱计算（见
   [agent-workflow.md](agent-workflow.md)）。

## 不做的事

- 不生成"看起来很酷但没人看"的全量大图：默认从搜索/当前文件出发，按需展开。
- 不把手写文档变成自动生成的堆砌物：L1 保持人写、可读、有判断。
- 不自动删除任何东西。
