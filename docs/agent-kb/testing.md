# 测试：选层级、避互斥、加回归

## 三个层级

```powershell
scripts\test.ps1            # smoke   ≈75 个，编译器闸门，秒级
scripts\test.ps1 standard   # ≈400 个，全部 conformance 程序，提交前基线
scripts\test.ps1 full       # ≈1035 个，加确定性/泄漏/自举
scripts\test.ps1 smoke -Match gui    # 按正则挑用例
```

底层就是 `ctest --test-dir build -C Release -L <tier>`；层级标签在 `CMakeLists.txt` 的
"Test tiers" 段落里定义。

**选层级的规矩**（`AGENTS.md`：小改动不要跑 1035 个）：

| 改动 | 至少跑 |
| --- | --- |
| 文档、注释 | 不用跑 |
| IDE/模板（不动标准库、不动编译器） | `smoke` + 编 IDE（`scripts\build_ide.ps1`） |
| 标准库（非 GUI） | `standard` |
| 标准库 GUI/主题/控件 | `standard` + `scripts\build_gallery.ps1` + 真实窗口看一眼 |
| 编译器任何一层 | `standard`；动了 ARC/async/泛型/发射再加 `full` |
| 新增诊断 | `standard` **必跑**：新诊断会炸出既有真实错误（见 debugging-playbook 第 3 节） |

## 互斥：什么不能同时跑

- **测试与构建互斥**：用例共用 `build\zanc.exe` 和标准库时间戳，一边跑测试一边编译，
  会让毫无关系的用例失败。`scripts\test.ps1` 的注释里明确写了这条。
- **gallery 与 IDE 构建互斥**：两者都会重写 `stdlib\Gui\CustomComponents.zan`
  （组件扫描产物）。串行跑。
- **桌面资源类用例互斥**：托盘/屏幕/输入/自动化（`conformance_win_tray_screen_smoke`、
  `*_win_automation_*`、`*_win_uielement_*` 等）会抢真实桌面资源，`-j` 并发下偶发失败。
  **判断规则**：并发跑失败 → 单独重跑那一个；单跑通过就是资源争用，不是功能回归；
  单跑仍失败才是真问题。

```powershell
ctest --test-dir build -R conformance_win_tray_screen_smoke --output-on-failure
```

## 目录与断言方式

| 目录 | 内容 | 驱动脚本 |
| --- | --- | --- |
| `tests/conformance/` (≈650) | 编译并运行，比对期望输出 | `run_case.cmake` |
| `tests/diag/` (26) | **编译期必须报错**，正则断言错误文本 | `run_compile_error.cmake` |
| `tests/golden/` | 输出/IR 黄金文件比对 | `run_determinism.cmake` 等 |
| `tests/gui/` | GUI 相关 | 见 `CMakeLists.txt` |
| `tests/leakprobe/`, `leak_*` 用例 | ARC 泄漏 | `run_leakcheck.cmake` |
| `tests/abi/`, `tests/emit_lib/` | ABI / 库发射 | `run_abi_case.cmake`, `run_emit_lib.cmake` |
| `tests/dap/`, `tests/fmt/`, `tests/doc/`, `tests/selfhost/` | 调试器、格式化、文档、自举 | 各自 `run_*.cmake` |
| `tests/fuzz/`, `tests/_probe/`, `tests/_scratch/` | 模糊测试与探针 | — |

加一个编译期诊断回归的最小形状（`CMakeLists.txt`）：

```cmake
foreach(_case class_member_read class_member_read_inherited)
  add_test(NAME diag_${_case}
    COMMAND ${CMAKE_COMMAND}
      -DZANC=$<TARGET_FILE:zanc>
      -DSRC=${CMAKE_SOURCE_DIR}/tests/diag/${_case}.zan
      -DOUT_EXE=${CMAKE_BINARY_DIR}/diag_${_case}${_exe_ext}
      "-DEXPECT_REGEX=has no member"
      -P ${CMAKE_SOURCE_DIR}/tests/run_compile_error.cmake)
  set_tests_properties(diag_${_case} PROPERTIES TIMEOUT 60)
endforeach()
```

一个诊断至少要两个用例：**该报的报**、**不该报的不报**（例如继承来的成员合法）。
只写前者的诊断，几乎一定会误报。

## 模板与项目级验证

```powershell
scripts\e2e_pipeline.ps1     # 遍历 templates\：脚手架 → 编译 → 发布 → 冒烟运行
```

它模拟 IDE 的 `CreateProjectT`/`CopyTreeT`，所以**模板加/删/改 manifest 后必跑**。
注意它对 `.zform` 设计器模板输出 `SKIP: designer template (.g.zan generated by the IDE)`
——窗体模板的代码生成由 IDE 触发，**这条路径不在无头测试覆盖内**，只能靠 IDE 里
真正新建一次项目来验证。这是当前覆盖上的已知缺口。

## GUI / UI 端到端

- `scripts\build_gallery.ps1` → `build\gallery_test.exe`：控件回归的主力。
- `scripts\shot_*.ps1`：启动程序、找窗口、点击、截图（`shot_ide_dialog.ps1` 专门截
  "新建项目"对话框；`shot_gallery.ps1`、`shot_designer.ps1`、`shot_theme.ps1` 等）。
- `scripts\drive_ide.ps1` + `ZAN_UI_SCRIPT`（`UiDriver.Tick()`）：脚本化驱动 IDE 做
  操作序列，用于可重复的 UI 流程回归。
- 这些脚本需要**可交互的桌面会话**：exe 必须能真正建出窗口。窗口起不来时
  `shot_*` 只会报 `not-found`，先按 debugging-playbook 第 4 节查原生依赖。

**"能编过" ≠ "能跑" ≠ "界面对"**。GUI 改动的验收下限是：gallery 能编且能起、
相关画面截图看过。
