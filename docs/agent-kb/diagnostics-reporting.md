# 帮助与反馈面板 · 错误上报（设计）

> 客户端先做，服务端与插件市场一起后做。原则：**默认不外发任何东西**，
> 用户看得见要发什么、能改、能拒。

## 面板内容（IDE 内置"帮助与反馈"）

1. **诊断日志**：本地聚合的最近错误（见下），可按来源/时间筛选，点击跳源码。
2. **一键导出/复制**：生成一份可粘贴的报告（Markdown/zip），让用户自己贴到 issue、
   群里、或交给智能体分析——**这条路径在没有服务端时就能完全跑通**。
3. **反馈入口**：类型（缺陷/建议/文档问题）+ 描述 + 复现步骤 + 可选附件（截图/日志片段）。
4. **已知问题 / 文档链接**：接内置文档浏览器（`ZanIDE.Docs.zan`）与在线索引。
5. **上报设置**：开关（默认关）、服务端地址、是否附带日志、是否附带源码片段、
   队列状态（待发/失败/已发）。

## 采集什么（本地聚合层）

统一收口，各来源打同一套结构：

| 来源 | 采集内容 |
| --- | --- |
| 编译器 `zanc` | 诊断（文件/行/列/等级/消息）、退出码、命令行、耗时；`error: code generation failed` 这类无细节错误要连同上文诊断一起留 |
| 运行/调试 | 程序退出码、stderr、未处理异常、崩溃点 |
| IDE 自身 | 未处理异常（已有：`<exe>/cache/ide_error.log`，见 `ZanIDE.CacheDir()`）、面板操作失败、LSP/DAP 断连 |
| 构建/发布 | 链接失败、缺失驱动 DLL（如"找不到 SDL3.dll"这类原生依赖问题） |
| 环境 | IDE 版本 + commit（`IdeVersion.zan`）、编译器版本、OS/架构、显示缩放、皮肤 |

**事件结构**（本地存 `<cache>/diagnostics/*.jsonl`，滚动上限）：

```jsonc
{
  "id": "uuid", "ts": 1730000000, "kind": "compiler|runtime|ide|build|lsp",
  "severity": "error|warning|crash",
  "code": "ZAN…|exit=1", "message": "…",
  "file": "src/…", "line": 12, "col": 65,     // 有就带
  "context": ["…上下几行诊断…"],
  "env": { "ide": "0.2.1", "commit": "…", "os": "…", "arch": "…" },
  "repro": ["用户填写或 IDE 记录的操作序列"],
  "attachments": []                            // 用户显式勾选才有
}
```

## 隐私红线

- **默认不上传**。开关关闭时只本地留存。
- 上传前**显示完整 payload 预览**（可编辑）。
- 默认**不带**：源码正文、项目路径全名（做相对化/哈希）、环境变量、密钥/令牌、
  数据库连接串、用户名。
- 源码片段只有用户勾选才带，并做**行范围裁剪**；上传前跑一遍脱敏（常见密钥形态、
  连接串、邮箱、绝对路径）。
- 允许"仅导出到本地文件"作为永久替代方案——用户可以自己审阅后再决定给谁。

## 上报通道（服务端后做，但协议先定）

```text
POST {endpoint}/v1/reports
Headers: Content-Type: application/json, X-Client: ZanIDE/<version>
Body: { client:{...}, events:[ …上面的事件… ], user_note, consent:{logs:bool, snippets:bool} }
→ 200 { id, dedup_of? }   幂等键 = 事件 id
```

客户端要求：

- **离线队列 + 指数退避重试**，队列可见可清空，失败不弹窗打扰。
- 端点可配置（自建/企业内网优先），未配置时上报按钮显示"未配置服务端 → 导出到文件"。
- 同一 `code+file+message` 做本地去重计数，只发一条带 `count`。

## 与插件市场共设计（后续）

市场客户端骨架已在 `src/ide_zan/Marketplace*.zan`。两者共用一套后端设施：
账号/匿名 id、客户端版本、签名与限流、内容审核入口。上报的错误如果来自某个插件/模板，
要能带上它的市场 id 与版本，便于把问题回流给发布者。

## 落地顺序

1. P1：本地聚合 + 面板展示 + 导出/复制（无网络能力）。
2. P2：反馈表单 + 脱敏与 payload 预览 + 端点配置（仍默认关闭）。
3. P3：队列/重试/去重 + 服务端接收端点（与市场一起）。
4. P4：回流闭环——已知问题库、按 `code` 匹配"这个错误已知，解决办法是…"。
